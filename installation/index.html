    Installation¶

    pip install multibench-sc installs the API on Linux or macOS, Python 3.9 or newer. Running a method also needs that method's environment, which is Linux-only and installed separately.

    TL;DR

    conda create -n multibench python=3.11 -y && conda activate multibench
pip install multibench-sc
python -c "import multibench as mtb; print(mtb.__version__)"

    Step 1, Create an isolated environment¶

    Any fresh Python 3.9+ environment works. Conda is optional: the method environments install without it.

    terminal
    conda create -n multibench python=3.11 -y
conda activate multibench
    terminal
    mamba create -n multibench python=3.11 -y
mamba activate multibench
    terminal
    python3.11 -m venv .venv
source .venv/bin/activate

    Step 2, Install multibench¶

    terminal
    pip install multibench-sc
    Details

    Dependencies. The install brings numpy, pandas, h5py, anndata, matplotlib, pyyaml, scanpy and scib. PyTorch, R and the method packages are not installed here; they live in each method's environment.

    Developer install. Clone the repository only to edit the notebooks or run the test suite:

    terminal
    git clone https://github.com/DSichang/scMultiBench.git
cd scMultiBench
pip install -e ".[dev]" --config-settings editable_mode=compat

    Step 3, Verify the install¶

    terminal
    python -c "import multibench as mtb; print(mtb.__version__)"

    These calls need no method environment:

    import multibench as mtb

print(mtb.list_tasks())
print(mtb.list_methods(category="vertical"))
print(mtb.describe_layout("vertical"))   # how to lay out your own dataset

    Method environments¶

    Each method runs in its own Linux environment, because the methods' dependencies conflict. Install only the ones you need; --packed downloads prebuilt archives. No conda binary is needed for the packed path.

    terminal
    multibench env doctor                                      # installed or missing, with the install line
multibench env plan --category vertical                    # environments a category needs, with sizes
multibench env install --methods SCALEX --packed --run     # one method
multibench env install --category vertical --packed --run  # one category
    Details

    Where they go. mtb.config.DEFAULT.envs_dir: $MULTIBENCH_ENVS_DIR when set, else the envs directory of the conda or mamba on PATH, else ~/.cache/multibench/envs.

    Without --packed. The environment is built from its lockfile, which needs conda or mamba and takes longer. A failed archive download also falls back to this build.

    CPU and GPU builds. On a host without an NVIDIA GPU, --packed installs the smaller CPU build of the PyTorch environments that have one. --flavor cpu or --flavor gpu overrides the choice.

    macOS and Windows. env install --run refuses unless you pass --force; dry runs work. The stored results, scan, evaluate and the plots work on any OS.

    Sizes. Categories share environments, so two categories cost less than the sum of their env plan totals. ? disk means the size on disk is not measured yet, so the disk total is a lower bound.

    Resuming. env install skips environments that already exist, so rerunning it resumes an interrupted install. With no --methods or --category it installs all 26; run multibench env plan first to see the total.

    From Python. mtb.env.status, plan, install, doctor and recipe mirror the CLI; mtb.env.install is a dry run until dry_run=False (reference).

    Method scripts. The first mtb.run clones the method scripts (PYangLab/scMultiBench) with git into mtb.config.DEFAULT.repo_path (~/.cache/multibench/scMultiBench_ref after pip install). On a host without network or git, copy a clone of that repository there, or pass its path as repo_path=.

    Custom launch. mtb.run(..., cmd_template=...) (--runner on the command line) replaces how the command is launched, for example with a container wrapper.

    Preview a run. --dry-run prints the command a run would execute, without running it:

    terminal
    multibench run --method SCALEX --category diagonal \
    --input rna=<data_path>/D28/rna.h5 --input atac_gas=<data_path>/D28/atac_gas.h5 \
    --out-dir runs/scalex_d28 --dry-run

    Google Colab¶

    The category tutorials open in Colab from their badge and run on the free CPU runtime. By default (INSTALL_ENVS = False) nothing is downloaded and the method cells use stored outputs; INSTALL_ENVS = True installs the environments and runs the methods.

    Details

    Default. Run all is safe: the run cells load the benchmark's stored outputs for the dataset, so evaluate scores real embeddings. Offline, the package's stored metric table is used instead, and a printed line says so.

    Running methods. INSTALL_ENVS = True needs Colab or a Linux host; on macOS the environment install refuses.

    GPU runtime. Choose one before setting the flag (Runtime -> Change runtime type -> T4 GPU). On a CPU runtime the CPU builds are installed and training methods run much slower.

    Download per tutorial. GPU builds: cross 3.0 GB, diagonal 5.1 GB, mosaic 5.5 GB, vertical 6.2 GB. CPU builds: cross 1.4 GB, diagonal 1.6 GB, mosaic 1.8 GB, vertical 1.5 GB.

    Get the data¶

    Each tutorial downloads its dataset on first run. Datasets go to mtb.config.DEFAULT.data_path: ~/.cache/multibench/data after pip install, <repo>/data in a developer install.

    import multibench as mtb

mtb.data.fetchable()      # ['D11', 'D28', 'D45', 'D46', 'D52']
mtb.data.fetch("D11")     # no-op when already present
    Details

    Sizes. D11 (vertical) 11 MB, D28 (diagonal) 137 MB, D45 (mosaic) 290 MB, D46 (mosaic) 97 MB, D52 (cross) 179 MB.

    Cache location. When XDG_CACHE_HOME is set, the pip-install data path is $XDG_CACHE_HOME/multibench/data.

    Manual download, for example D11:

    terminal
    DATA=$(python -c 'import multibench as mtb; print(mtb.config.DEFAULT.data_path)')
mkdir -p "$DATA" && wget -qO- https://github.com/DSichang/scMultiBench/releases/download/data-v1/D11.tar.gz | tar xz -C "$DATA"

    Other datasets. The full collection of processed datasets is linked from the scMultiBench README. Unpack a dataset under the data path, or anywhere else and pass data_path= (--data-path on the command line). dataset is the folder name; data_path is the folder that contains it.

    Upgrading from 0.2.1¶

    0.3 renamed a few functions and merged the metric selectors into one metrics= argument. Some old spellings still work in 0.3 with a DeprecationWarning; others were removed and raise an error. The old -> new table is in the API reference.

    Troubleshooting¶

    OSError: conda env '<env>' (<method>) is not installed

    The method's environment is missing. Run the install command the message names, for example multibench env install --methods <method> --packed --run.

    scan() shows the same per method in its env_ok column.

    FileNotFoundError: ... 'conda' from mtb.run

    No method environment is installed yet and this host has no conda. Install the method's environment with multibench env install --methods <method> --packed --run.

    OSError naming envs_dir, with MULTIBENCH_RUN_MODE=prefix

    Prefix mode is forced, but the environment is not under envs_dir.

    Install it (multibench env install --methods <method> --packed --run), point MULTIBENCH_ENVS_DIR at the folder that holds it, or unset MULTIBENCH_RUN_MODE.

    RuntimeError: no conda/mamba on this host; <env> has a packed archive - pass packed=True

    Only a lockfile build needs conda. Pass packed=True (--packed on the command line).

    ImportError: No module named scib from mtb.evaluate

    multibench was installed with --no-deps or into another interpreter. Run pip install multibench-sc in the environment you import from.

    cLISI / iLISI are NaN, with a warning naming knn_graph.o

    Both need scib's compiled LISI helper, which ships as a Linux x86-64 binary. On other platforms evaluate() rebuilds it automatically when a C++ compiler (g++, c++ or clang++) is on PATH.

    Without a compiler, install one (Xcode command-line tools on macOS) and rerun evaluate in a new Python session, or run the g++ command the warning prints. The other metrics are computed either way.

    unsupported input format from mtb.io.to_canonical

    Accepted inputs: .h5ad, .h5mu, .csv / .tsv, .loom, in-memory AnnData / MuData, or an already-canonical scMultiBench .h5. Convert other formats first.

    For a whole dataset folder, use mtb.io.export_dataset or multibench convert.

    Still broken? Open an issue with the output of python -c "import multibench as mtb; print(mtb.__version__)" and pip freeze.
