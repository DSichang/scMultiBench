    Quickstart¶

    scMultiBench wraps the 40-method single-cell multimodal integration benchmark behind one clean Python surface, imported as multibench and aliased mtb by convention. This page walks the full loop in five steps: discover the methods that fit your data, plot the stored benchmark, run a method, evaluate that run, and plot your own result alongside the rest. Everything but step 3 runs on a laptop with pip install multibench-sc; step 3 needs the method's conda environment.

    TL;DR

    import multibench as mtb, pandas as pd

# 1. what can integrate unpaired RNA + ATAC (diagonal)?
mtb.find_methods(category="diagonal", modalities=["rna", "atac"])

# 2. plot the published diagonal benchmark for dataset D28
df = mtb.load_results("diagonal", dataset="D28")
mtb.plot.bubble(df, metrics=["ARI", "NMI", "ASW"], save="fig.pdf")

# 3. run a method on the fetchable D28 (needs the method's conda env)
mtb.data.fetch("D28")
res = mtb.run("SCALEX", "diagonal",
              inputs=mtb.inputs_for("D28", "diagonal", "SCALEX"),   # (dataset, category, method)
              out_dir="/abs/path/out/scalex_d28")

# 4. score it with scIB metrics (labels_for returns the files in the embedding's cell order)
metrics = mtb.evaluate(res.output, labels=mtb.labels_for("D28"), metrics="clustering")

# 5. reshape and plot it next to the benchmark
mine = mtb.to_long(metrics, method="SCALEX_rerun", dataset="D28", category="diagonal")
mtb.plot.bubble(pd.concat([df, mine]), metrics=["ARI", "NMI", "ASW"])

    Step 1 - Discover methods for your data¶

    The benchmark spans four integration categories - vertical (paired, same cells), diagonal (unpaired, bridged by features), mosaic (overlapping modalities with a bridge), and cross (fully-matched datasets). Start by filtering the registry down to the methods that consume your modalities.

    import multibench as mtb

mtb.find_methods(category="diagonal", modalities=["rna", "atac"])
# -> ['SCALEX', 'Seurat_v5', 'scBridge', 'VIPCCA', 'Portal', 'uniPort', 'sciCAN', 'scJoint', 'GLUE',
#     'MultiMAP', 'iNMF', 'online_iNMF', 'Conos', 'Seurat_v3']

    find_methods accepts any combination of category, task, needs_labels, atac, modalities, runnable, tunable and available - every filter is ANDed and judged per variant (a method matches when one of its variants satisfies category, modalities, needs_labels and atac together), and a typo in any token raises ValueError naming the valid vocabulary. Once you have a candidate, inspect its spec and what it has been observed to cost:

    info = mtb.method_info("SCALEX")
info["env"], info["atac"], info["needs_labels"], info["reference"]["doi"]
# ('scmb_torch', 'gene_activity', False, '10.1038/s41467-022-33758-z')
info["runtime"]
# {'observed': [{'cells': 11014, 'dataset': 'D28', 'sec': 2233, 'source': 'manual'}], 'tier': 'slow', 'worst_sec': 2233}
mtb.recommend("diagonal", modalities=["rna", "atac"])   # ranked from the stored tables, with coverage

    recommend makes coverage explicit (n_datasets, coverage per method) and does not hide what it could not score: a method wired for the category with no rows in the chosen source is listed with grand_score NaN, one warning names it (and suggests source="rerun" when that source has it), and metrics="batch" ranks on the batch-correction metrics instead.

    Step 2 - Plot the stored results¶

    Before running anything, you can reproduce the paper's scIB-style bubble tables straight from the shipped metric tables. load_results returns a tidy long frame (metric, value, method, dataset, category, clustering, source); plot.bubble turns it into a figure where each circle's radius tracks the method's rank and its fill tracks the metric value, with an Overall bar per metric family.

    df = mtb.load_results("diagonal", dataset="D28")          # the paper's table, 14 methods
fig = mtb.plot.bubble(df, metrics=["ARI", "NMI", "ASW"], save="fig.pdf")

    load_results also takes methods, metrics ("clustering" / "batch" / "all", or a list of codes such as ["ARI", "NMI"]), clustering ("default", "louvain", or "kmeans") and source - "published" (the paper's numbers, default) or "rerun" (the package's own sweep, the tables behind the category tutorials). The two cover different methods - the paper's cross table for D52 holds one method where the sweep holds eight - so name the source whenever the count matters; mtb.results_coverage(category) says what each holds per dataset. To rank methods across several datasets instead of within one, pass aggregate="summary" to plot.bubble, which averages each method's per-dataset ranks.

    Step 3 - Run a method¶

    mtb.run builds the method's real command line, executes it in the method's own conda environment, and loads the typed output back into Python. inputs is a dict mapping each modality role to a file path; inputs_for resolves them for a benchmark dataset, and non-canonical inputs are auto-converted to the canonical scMultiBench .h5 first (pass convert=False to skip this). The method scripts themselves are never modified.

    mtb.data.fetch("D28")                                      # 137 MB; no-op when present
res = mtb.run(
    method="SCALEX",
    category="diagonal",
    inputs=mtb.inputs_for("D28", "diagonal", "SCALEX"),    # {'rna': .../D28/rna.h5, 'atac_gas': .../D28/atac_gas.h5}
    out_dir="/abs/path/out/scalex_d28",
)

res.output      # the joint embedding, (11014, 10): 6,408 RNA + 4,606 ATAC cells x latent dims
res.cmd         # the exact argv that was executed
res.extra       # dict of any additional outputs
res.stdout      # captured stdout / stderr

    The return value is a RunResult with fields method, out_dir, cmd, output, extra, stdout, and stderr.

    Each method runs in its own conda env

    run orchestrates per-tool environments via the default cmd_template="conda run -n {env} {cmd}", so the target env (for SCALEX, scmb_torch, from method_info(...)["env"]) must exist: multibench env install --methods SCALEX --packed --run builds it, and run raises OSError (EnvironmentError is its alias) with that command when it is missing. To run inside the current interpreter instead, pass cmd_template="{cmd}". inputs and out_dir may be relative: run makes every path absolute before it builds the command (the script runs with out_dir as its working directory), and inputs_for returns absolute paths. The same call from the shell, checked without executing anything:

    terminal
    multibench run --method SCALEX --category diagonal \
    --input rna=<data_path>/D28/rna.h5 --input atac_gas=<data_path>/D28/atac_gas.h5 \
    --out-dir out/scalex_d28 --dry-run     # prints `conda run -n scmb_torch python .../main_SCALEX.py ...`; drop --dry-run to execute

    Your own data. mtb.run_all(dataset, category, out_dir=...) runs every method that fits a dataset folder and scores the outputs - the category tutorials are built on it. mtb.describe_layout(category) prints how that folder is laid out (role -> filename, label files, the ATAC caveats), and one call writes it from an AnnData:

    print(mtb.describe_layout("vertical"))          # the folder layout export_dataset writes, role by role
mtb.io.export_dataset(adata, "data/MYCITE", rna="X", adt="obsm:protein", labels="obs:celltype")
mtb.scan("MYCITE", "vertical", data_path="data")     # files_ok / env_ok per method, with reasons
res = mtb.run_all("MYCITE", "vertical", data_path="data", out_dir="out/")
res.summary; res.plot()

    Step 4 - Evaluate your run¶

    mtb.evaluate computes scIB metrics on a run output and returns a metric.csv-shaped frame (index = metric name, single "Value" column). Clustering metrics need the ground-truth cell-type labels; clustering is optional (omitted, scIB's optimal-resolution Leiden clustering is derived from the embedding). metrics= selects what is computed: None (the default) is every applicable metric - the clustering family, plus the batch family when a batch vector exists (or labels is a list of label files, one per batch); "clustering", "batch" and "all" name a family, a list of codes names exactly those.

    metrics = mtb.evaluate(
    res.output,
    labels=mtb.labels_for("D28"),   # {'rna_cty': ..., 'atac_cty': ...} - one file per modality, in the
    metrics="clustering",           # order SCALEX stacks the cells (RNA first, then ATAC)
)
# index: ARI, NMI, ASW, iASW, iF1, cLISI   column: Value

    labels_for returns a multi-file dataset's label files in the benchmark's cell-stacking order, so the dict goes in as is (a dict in any other order needs label_order=; the default metrics=None - or metrics="all" - then uses each cell's file of origin as its batch and adds the batch family). labels can equally be a pandas.Series, an array, or an obs column name when output is an AnnData; metrics=["ARI", "NMI"] restricts the computation. ARI, NMI and iF1 need scIB's Leiden resolution sweep - tens of seconds for a few thousand cells, minutes for ~10^4 - which evaluate announces on stderr above 2,000 cells (verbose=False silences it); clustering= (your own assignment) or a metrics=[...] list of metrics that do not need it (ASW, iASW, cLISI, the batch family) skips the sweep.

    Step 5 - Plot your own result¶

    To compare your run against the benchmark, reshape evaluate's wide frame into the same seven-column long format load_results produces (source="user", clustering="default"), then hand it to plot.bubble, concatenated with the stored frame from Step 2. Give your run a name of its own - the stored table already holds a SCALEX row, and duplicate (method, metric) rows raise rather than being silently averaged.

    import pandas as pd

mine = mtb.to_long(metrics, method="SCALEX_rerun", dataset="D28", category="diagonal")

combined = pd.concat([df, mine], ignore_index=True)
mtb.plot.bubble(combined, metrics=["ARI", "NMI", "ASW"],
                title="D28: published table + our SCALEX re-run", save="compare.pdf")

    Both frames are the same dataset, so the figure is a like-for-like comparison; a re-run does not reproduce the stored decimals exactly (methods are stochastic), so read ranks rather than digits - see Are my numbers comparable?. When you concatenate your dataset with a benchmark dataset instead, the comparison is cross-dataset: aggregate="dataset" then averages each method's values across the datasets it appears in (with a warning and dataset-tagged row labels), and aggregate="summary" ranks within each dataset first.

    The same loop is available from the command line:

    terminal
    multibench plot bubble --category diagonal --dataset D28 \
    --metrics ARI,NMI,ASW --out fig.pdf
multibench evaluate --output out/scalex_d28/embedding.h5 --labels <data_path>/D28/rna_cty.csv \
    --method SCALEX_rerun --dataset D28 --category diagonal --out mine.csv    # mtb.labels_for("D28") returns these paths
multibench plot bubble --input mine.csv --category diagonal --dataset D28 \
    --metrics ARI,NMI,ASW --out compare.pdf                                  # your rows next to the stored table

    multibench also exposes list, find, params, scan, layout, convert, run, run-all, cite and env (status / plan / doctor / install / recipe) subcommands that mirror the Python API - multibench <command> --help documents every flag. scan prints a compact table by default (--columns all or --format csv|tsv|json for every column, command included), run-all --dry-run prints the same table plus the exact command per variant, run --dry-run the one command, --param METHOD:KEY=VALUE sets hyperparameters and params METHOD lists them; evaluate --metrics takes a family token or a comma list; plot --input is repeatable and, combined with --category, overlays your rows on the stored table; data goes to stdout, progress and notes to stderr.
