    API reference¶

    The package is imported as import multibench as mtb. The tables below list every public function by step; each name links to its reference entry (signature, parameters, examples).

    The five layers¶

    A benchmark run has five steps: discover a method, prepare the data, run, score, compare.

    import multibench as mtb

mtb.find_methods(category="vertical", modalities=["rna", "adt"])          # 1. discover
mtb.io.export_dataset(mdata, "data/MYCITE", rna="rna", adt="adt",
                      labels="rna:celltype")                               # 2. prepare
batch = mtb.run_all("MYCITE", "vertical", out_dir="runs/MYCITE",
                    data_path="data")                                      # 3. run (+ score)
res = mtb.run("Matilda", "vertical", out_dir="runs/Matilda",
              inputs=mtb.inputs_for("MYCITE", "vertical", "Matilda",
                                    data_path="data"))                     #    ... or one method
scores = mtb.evaluate(res.output,
                      labels=mtb.labels_for("MYCITE", "vertical", "Matilda",
                                            data_path="data"))             # 4. score
stored = mtb.load_results("vertical", dataset="D11")                       # 5. compare
mtb.plot.bubble(stored)
    Details

    Your rows next to the stored ones. mtb.to_long turns the scores into the long frame that mtb.load_results returns, so both can be concatenated and drawn with mtb.plot.bubble.

    Same Leiden backend. Set mtb.config.DEFAULT.leiden_flavor = "leidenalg" before mtb.evaluate so your ARI, NMI and iF1 use the backend of the published tables.

    1. Discover¶

    Which methods exist, what each needs, how to cite it. Nothing is downloaded.

    entry point what it does
    mtb.list_methods Method ids, optionally for one category.
    mtb.find_methods Method ids matching every filter given (category, task, modalities, ...).
    mtb.method_info Everything the registry holds on one method: environment, variants, runtime, GPU needs, reference.
    mtb.params_for The hyperparameters a method variant accepts, with their defaults.
    mtb.describe_layout How to lay out your own dataset folder for a category.
    mtb.cite Citation text or BibTeX for the benchmark and the methods you ran.
    mtb.list_tasks The valid task values.
    mtb.list_categories The valid category values, each with a short description.

    2. Prepare data¶

    Put your matrices into a dataset folder and find the files a method reads.

    entry point what it does
    mtb.io.export_dataset Write an AnnData / MuData (or loose matrices) as a dataset folder.
    mtb.io.to_canonical Convert one matrix to the canonical .h5 (features x cells).
    mtb.io.read_canonical Read a canonical .h5 back as an AnnData (cells x features).
    mtb.io.normalize_peak_names Write a copy of a canonical .h5 with ATAC peak names spelled the way the methods expect.
    mtb.inputs_for {role: path} of the files a method variant reads from a dataset folder.
    mtb.labels_for {name: path} of a dataset's cell-type label CSVs; with category and method, in the order that method stacks its cells.
    mtb.data.fetch Download the named reference datasets unless they are already present.
    mtb.data.fetch_outputs Download precomputed run_all outputs for a tutorial dataset.
    mtb.data.fetchable The dataset ids fetch can download.

    3. Run¶

    Run methods in their environments. mtb.scan shows what can run before you start.

    entry point what it does
    mtb.scan Which methods can run on a dataset, why the others cannot, and the command each would run.
    mtb.run Run one method and load its output (a RunResult).
    mtb.run_all Run and score every applicable method; returns a BatchResult.
    mtb.sweep Run one method over a range of one hyperparameter.
    mtb.load_batch Reload a saved BatchResult.
    mtb.BatchResult What run_all returns: a summary table, a long frame, a figure, rescoring.
    mtb.env.status Which method environments are installed on this machine.
    mtb.env.plan Which environments a set of methods needs, with download and disk sizes.
    mtb.env.install Install those environments; a dry run until dry_run=False.
    mtb.env.doctor What is installed, what is missing, and the install command for the gaps.
    mtb.env.recipe The build recipe of one method's environment.

    4. Score¶

    Compute scIB metrics for a run output.

    entry point what it does
    mtb.evaluate scIB metrics of a run output against cell-type labels (and batch labels).
    mtb.to_long Reshape evaluate's result into the long results frame.

    5. Compare¶

    Load the stored metric tables, rank methods and draw figures.

    entry point what it does
    mtb.load_results The stored metric tables as one long frame.
    mtb.available_datasets Dataset ids with stored results.
    mtb.results_coverage Which (category, dataset, method) combinations have results, and from which source.
    mtb.recommend Rank methods for a category from the stored results, with coverage shown.
    mtb.DegenerateRerunWarning Warning class for a re-run row that most likely failed silently.
    mtb.plot.bubble Bubble table of a long results frame.
    mtb.plot.bar Each method's overall score across datasets, as bars.
    mtb.plot.build_table The numbers behind a bubble table, without drawing it.
    mtb.plot.BubbleTable What build_table returns: per-family matrices, ranks and row order.
    mtb.catalog.methods The methods table as a DataFrame.
    mtb.catalog.datasets The datasets table, including which datasets have stored results.
    mtb.catalog.metrics The metrics table, with a description of each metric.
    mtb.catalog.canonical_id The canonical method id for any known spelling.
    mtb.catalog.canonical_metric The canonical metric code for any known spelling ("ari" -> "ARI").
    mtb.catalog.known_metrics The metric codes, in family order.

    Configuration and errors¶

    The environment variables are listed on the config page.

    entry point what it does
    mtb.config.Config Paths and settings (data_path, envs_dir, leiden_flavor); every function reads mtb.config.DEFAULT.
    mtb.AmbiguousVariantError Raised when a method has several variants and neither modalities= nor the dataset's files select one.

    The same story from the shell¶

    Each multibench subcommand wraps one Python function and takes the same argument names. multibench <command> --help lists the flags.

    terminal
    multibench layout vertical                         # how to lay out your data
multibench convert my.h5ad data/MYCITE --rna X --adt obsm:protein --labels obs:celltype
multibench scan MYCITE --category vertical --data-path data
multibench params Matilda                          # the hyperparameters --param accepts
multibench run --method Matilda --category vertical --out-dir runs/Matilda \
    --input rna=data/MYCITE/rna.h5 --input adt=data/MYCITE/adt.h5 --input cty=data/MYCITE/cty.csv
multibench evaluate --output runs/Matilda/embedding.h5 --labels data/MYCITE/cty.csv \
    --method Matilda --dataset MYCITE --category vertical --out runs/Matilda/long.csv
multibench run-all MYCITE --category vertical --data-path data --out-dir runs/MYCITE
multibench plot bubble --input runs/MYCITE --out mine.pdf               # your runs
multibench plot bubble --category vertical --dataset D11 --out d11.pdf   # a stored table
multibench cite Matilda MOFA2
    Details

    Output. Tables, ids and commands go to stdout. Progress, warnings and errors go to stderr, so 2>/dev/null hides them.

    Full tables. scan and run-all --dry-run clip long text to 80 characters. --columns all or --format csv|tsv|json prints every column in full, including command.

    Dry run. run --dry-run prints the command without running it.

    Hyperparameters. params METHOD lists them per variant. Set one with --param KEY=VALUE on run, or --param METHOD:KEY=VALUE on run-all.

    Metrics. evaluate --metrics takes a family (clustering, batch, all) or a comma-separated list of codes.

    Overlay. plot --input together with --category adds your rows to the stored table. --dataset filters both, so your rows must be for a dataset the stored table has.

    Leiden backend. multibench evaluate uses the default igraph backend, not the leidenalg backend of the published tables, and has no option to change it. To match them, score in Python with leiden_flavor = "leidenalg".

    ATAC data. Pass --category to convert so the ATAC file gets the name that category expects.

    Environments. The env commands are dry runs until --run.

    Exit codes. 0 success, 1 runtime error (MULTIBENCH_DEBUG=1 prints the traceback), 2 usage error.

    Errors and warnings¶

    An invalid argument raises a standard exception whose message names the valid values or the fix.

    Details
    • KeyError: unknown method id, with a did-you-mean hint.
    • ValueError: unknown category, task, atac or modality token; the message lists the valid values.
    • TypeError: a single string where a list is expected (methods="StabMap"); the message shows the list form.
    • FileNotFoundError: missing dataset folder or file; the message lists the folders that exist, or the path and the working directory.
    • mtb.AmbiguousVariantError: a method with several variants that neither modalities= nor the dataset's files select. It is a ValueError and also a KeyError.
    • OSError: the method's environment is not installed; the message names the install command.

    Warnings are UserWarnings. The one for a re-run row that most likely failed silently is mtb.DegenerateRerunWarning, so you can filter on it.

    The metrics= vocabulary¶

    evaluate, load_results, recommend and BatchResult.rescore take the same selector: "clustering", "batch", "all", or a list of metric codes such as ["ARI", "NMI"].

    Details

    Families.

    • "clustering": ARI, NMI, ASW, iASW, iF1, cLISI (mtb.plot.CLUSTERING_METRICS).
    • "batch": ASW_batch, GC, iLISI, kBET (mtb.plot.BATCH_METRICS).
    • "all": both families; evaluate then needs batch labels.

    Default (None). evaluate computes the clustering family, plus the batch family when batch labels are available. load_results keeps every metric; recommend ranks on the clustering family.

    kBET. evaluate computes kBET only when it is named in a list.

    Errors. A single code still goes in a list (metrics=["ARI"]). A task name or an unknown code raises ValueError listing the valid values.

    Leiden backend. ARI, NMI and iF1 use a Leiden clustering sweep whose backend is mtb.config.DEFAULT.leiden_flavor: "igraph" (default, faster) or "leidenalg" (the backend of the published tables). The two can differ by up to about 0.1 ARI on the same embedding. Score the runs you compare with the same backend.

    Older scanpy. With scanpy older than 1.10, leidenalg is used.

    Method environments¶

    Each method runs in a linux-64 environment, shared with compatible methods (mtb.method_info(m)["env"]), installed with mtb.env.install. On macOS and Windows only the dry run works; a real install refuses unless force=True (--force).

    Details

    Method scripts. The upstream scripts run unmodified. The package builds the command, converts the inputs and loads the output.

    Run modes: prefix and conda¶

    mtb.run activates an installed environment directly from its folder under envs_dir (prefix mode, no conda needed), or falls back to conda run -n <env> (conda mode). MULTIBENCH_RUN_MODE=conda|prefix forces one.

    Details

    Prefix mode. The command runs as bash -c '<activate>; exec "$@"' -- <cmd>. <activate> sets CONDA_PREFIX, CONDA_DEFAULT_ENV and PATH, and sources the environment's etc/conda/activate.d/*.sh scripts.

    Forced prefix mode with no environment folder on disk raises OSError.

    Custom wrapper. cmd_template= on mtb.run replaces both modes.

    Installed or not. mtb.env.env_prefix returns the folder mtb.run would activate, or None. mtb.scan's env_ok column uses the same test.

    Archive flavours: cpu and gpu¶

    Five torch environments have a CUDA build and a smaller CPU-only build. mtb.env.install picks the CPU build when mtb.env.host_has_gpu finds no NVIDIA GPU.

    Details

    Which environments. env_sciPENN, matilda, scmb_scjoint, scmb_torch, scmb_scmm2.

    Choosing a build. flavor="cpu" or flavor="gpu" (--flavor on the CLI) overrides the default "auto".

    Same name either way. Both builds install under the environment's own name, so mtb.run and mtb.scan need no change. mtb.env.status() reports the installed build as flavor.

    GPU or CPU?¶

    Six methods need an NVIDIA GPU (mtb.method_info(m)["requires_gpu"]). Without one, mtb.run raises OSError before starting and mtb.scan gives the reason. The other methods run without a GPU.

    Details

    GPU-only methods. scBridge, moETM, SMILE, sciCAN, UnitedNet, iPOLNG.

    CPU switches. For scripts that use CUDA by default, method_info(m)["cpu_params"] holds the values that turn it off (scJoint use_cuda='', scMDC device='cpu'). Without a GPU, mtb.run adds them unless you set the key yourself; run(..., dry_run=True) shows the command.

    Always on CPU. scMM, scMVP and scMSI run on CPU, also on a GPU host.

    RunResult¶

    mtb.run returns a RunResult. Its output is the method's primary output (for example the embedding), ready for mtb.evaluate.

    Details

    Fields.

    • method: the method id.
    • out_dir: the working directory of the run.
    • cmd: the full command that ran, including the environment wrapper.
    • output: the primary output, loaded. An embedding may be dims x cells; evaluate re-orients it.
    • extra: {file: loaded output} for the method's extra outputs.
    • stdout, stderr: the captured streams.

    Failures. A non-zero exit raises RuntimeError with the end of the output. A missing environment raises OSError before anything is written; on a host with no environment and no conda, the run fails with FileNotFoundError for conda instead.

    Version¶

    mtb.__version__ is the installed version.
