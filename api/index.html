    API reference¶

    The scMultiBench API (imported as multibench, aliased throughout the docs as mtb) exposes a small, flat, free-function API organised into a handful of namespaces:

    • mtb.* - the top-level surface: the benchmark workflow (scan, plan, run_all, describe_layout), run one method, evaluate an output, to_long to reshape it, stored results (load_results, results_coverage, recommend), and discovery helpers (list_methods, find_methods, method_info, cite, inputs_for, labels_for, runtime_hint).
    • mtb.plot.* - scIB-style figures (bubble, bar).
    • mtb.eval.* - the evaluation pipeline (evaluate, to_long).
    • mtb.io.* - the canonical-format adapter (export_dataset, from_mudata, to_canonical, write_labels, read_canonical).
    • mtb.data.* - fetch the reference datasets.
    • mtb.catalog.* - typed views of the benchmark's metadata tables.
    • mtb.config.* - resolved paths and on-disk token maps.
    • mtb.env.* - per-method conda environments: status, plan, provisioning.

    The end-to-end story: mtb.io.export_dataset writes your data as a dataset folder, mtb.scan says which methods can run on it, mtb.run_all runs and scores them into a BatchResult whose .long frame - the same tidy frame mtb.load_results returns for the stored benchmark - goes into mtb.plot.bubble. Underneath, mtb.run returns a RunResult whose output flows into mtb.evaluate, and mtb.to_long reshapes that into the same long frame. The same story from the shell:

    terminal
    multibench layout vertical                         # how to lay out MY data
multibench convert my.h5ad data/MYCITE --rna X --adt obsm:protein --labels obs:celltype
multibench scan MYCITE --category vertical --data-path data
multibench params Matilda                          # the hyperparameters --param accepts, per variant
multibench run --method Matilda --category vertical --input rna=... --out-dir runs/Matilda
multibench evaluate --output runs/Matilda/embedding.h5 --labels data/MYCITE/cty.csv \
    --method Matilda --dataset MYCITE --category vertical --out runs/Matilda/long.csv
multibench plot bubble --category vertical --dataset D11 --out fig.pdf
multibench plot bubble --input runs/Matilda/long.csv --category vertical --dataset D11 --out fig.pdf   # overlay
multibench cite Matilda MOFA2

    Every subcommand wraps exactly one Python function with the same flag names; multibench <command> --help documents every flag. Tables, ids and commands go to stdout; progress ([run_all] ...), # dry run notes, warning: ... and error: ... go to stderr, so 2>/dev/null silences the chatter. scan and run-all --dry-run print a compact table (method, modalities, runnable, files_ok, env_ok, runtime_tier, reason, long text clipped to 80 chars); --columns all or --format csv|tsv|json gives every column unclipped. run-all --dry-run also prints the exact command line run() would execute per variant whose inputs resolve (paths absolutized, exactly as run passes them), run --dry-run prints the one command, --param/-p METHOD:KEY=VALUE (KEY=VALUE on run) sets hyperparameters and params METHOD lists them per variant with the values the script pins. plot --input is repeatable and, together with --category, overlays your rows on the stored table; convert takes --category (the ATAC filename rule) and copies an already-canonical .h5 instead of re-encoding it. The env commands are dry runs until --run, print a warning: ... linux-64 line on a non-Linux host, and env install --run refuses there unless --force. Exit codes: 0 ok, 1 a runtime error (error: ... on stderr; MULTIBENCH_DEBUG=1 shows the traceback), 2 a usage error.

    Method environments

    Running a method shells out to the conda environment it shares with other compatible tools via conda run -n <env> <cmd>, where <env> is mtb.env.group_for(method) - the same env multibench env install provisions (overridable through cmd_template). The original method scripts are never modified - multibench only builds the command, converts inputs to the canonical .h5, and loads the typed output.

    Error vocabulary

    Every entry point validates its tokens the same way: an unknown method id raises KeyError with a did-you-mean hint; an unknown category, task, atac or modality token raises ValueError listing the valid values; a bare string where a list of ids / tokens is expected (methods="StabMap", modalities="rna") raises TypeError showing the list form; a missing dataset folder or file raises FileNotFoundError listing the folders that exist (or the path and the current directory); a method with several variants that neither modalities= nor the folder's files single out raises mtb.AmbiguousVariantError - a ValueError that also matches KeyError, listing the modality-sets and the folder's contents; a missing conda env raises OSError naming the install command. Warnings are UserWarnings, one of them a subclass you can filter on: mtb.DegenerateRerunWarning (a re-run row that most likely failed silently). Nothing silently returns an empty result.

    Benchmark workflow¶

    The four category tutorials are built on these functions.

    mtb.scan¶

    mtb.scan(dataset: str, category: str | None = None, data_path: Path | str | None = None, *,
         methods: list[str] | None = None, modalities: list[str] | None = None,
         verbose: bool = False) -> pd.DataFrame

    Report every method that can run on dataset, and why the rest cannot. One row per (method, category, modalities) variant with two independent gates:

    • files_ok / files_reason - the input files resolve on disk, are oriented features x cells, every label CSV has one row per cell of the modality it labels, and a data_dir method finds what it needs (>= 2 .h5ad slices with obsm['spatial'] for registration). This gate always runs, whether or not any conda env is installed - a laptop without environments still tells you whether your layout is right.
    • env_ok / env_reason - the method's conda env exists on this machine; the reason names the env and the one-method install command.

    runnable = files_ok & env_ok; reason joins the non-empty reasons (empty iff runnable) in a SHORT form - the exception class, the method/dataset/category: prefix and the absolute directory are dropped (input files not found on disk: {'atac': 'atac.h5'}. Available files in D11: [...]), while files_reason / env_reason keep the verbatim text with full paths. Further columns: modalities (a +-joined string here, e.g. "rna+adt"; run_all / inputs_for take a list - split on "+"; "(data_dir)" marks a method that consumes a whole directory), env, output_kind, n_tunable, needs_labels (does this variant demand a label file), atac ('peak' / 'gene_activity' / None), runtime_tier / observed_worst_sec (measured, see runtime_hint) and caveat (known content traps: an ATAC role resolved to the wrong representation in either direction - a peak matrix fed to a gene-activity method, or a non-peak matrix fed to a peak method - judged per role from method_info(m)["atac"]). The one method whose script is not published - SPIRAL, method_info(m)["availability"] == "benchmark-host-only" - fails the file gate with files_reason benchmark-host-only: script not published: .... GPSA ships as a package driver and is public. Nothing is executed.

    Parameters

    • dataset (str) - folder NAME under data_path (not a path); a missing folder raises FileNotFoundError listing the folders that do exist.
    • category (str | None) - restrict to one category (ValueError on a typo); default all four.
    • data_path (Path | str | None) - the folder that CONTAINS dataset; default the configured data root.
    • methods (list[str] | None, keyword-only) - restrict to these ids (KeyError with a hint on a typo; a bare string raises TypeError); blocked rows are kept with their reason.
    • modalities (list[str] | None, keyword-only) - restrict to one modality combination (["rna", "adt"]; protein accepted for adt; a bare string raises TypeError). An exact selector, so directory-input variants ("(data_dir)") are excluded by any non-empty list - a UserWarning names them and says modalities=[] selects exactly them.
    • verbose (bool) - print [scan] files OK for k/n method rows; e/n envs installed.

    mtb.plan¶

    mtb.plan(dataset: str, category: str, *, methods: list[str] | None = None,
         modalities: list[str] | None = None, data_path: Path | str | None = None,
         verbose: bool = False) -> pd.DataFrame

    What run_all WOULD attempt - exactly the frame run_all(..., dry_run=True) returns, without an out_dir: scan restricted to methods / modalities, runnable rows first, blocked rows kept with reason and the files_ok / env_ok columns, plus a command column - the exact shell line run() would execute per variant whose inputs resolve (what multibench run-all --dry-run prints; out_dir defaults to the literal placeholder <out_dir> so a preview needs no directory - pass the real one for paste-ready lines). Never empty: ValueError when no variant of the requested methods exists under category. Filter plan[plan.runnable] for what will actually run. mtb.plan_commands(dataset, category, *, out_dir="<out_dir>", methods=, modalities=, data_path=, params=) returns the same frame (kept as the explicit spelling); mtb.command_preview(method, category, *, inputs, out_dir, params=, cmd_template=, repo_path=) returns the argv list for one call, the form behind multibench run --dry-run. Both absolutize the paths exactly as run does, and neither fetches or writes anything.

    mtb.run_all¶

    mtb.run_all(dataset: str, category: str, *, out_dir, modalities=None, methods=None,
            params: dict | None = None, data_path=None, evaluate: bool = True,
            dry_run: bool = False, verbose: bool = True, timeout: float | None = None,
            skip_existing: bool = False, batch=None) -> BatchResult   # DataFrame when dry_run=True

    Run every method that scan marks runnable (or the methods= subset) on dataset end to end - inputs, the method's own conda env, output loading, metrics - and collect everything in a BatchResult. A method that fails becomes a row in .failures, never an exception. When nothing is runnable the ValueError lists one line per requested variant with its own reason (or the first 3 of N blocked variants when methods= was not given); a requested method with no variant in the category raises plan's no <category> variant matches ....

    Parameters

    • dataset / data_path - as in scan.
    • out_dir - one sub-directory per method; ignored (may be None) when dry_run=True.
    • methods (list[str] | None) - restrict to these ids (KeyError + hint on a typo).
    • modalities (list[str] | None) - restrict to ONE modality combination, e.g. ["rna", "atac_gas"] (gene activity) vs ["rna", "atac_peak"] (peaks). The two ATAC representations do NOT map to the obvious filenames - see describe_layout.
    • params (dict | None) - per-method hyperparameters, {"Cobolt": {"lr": 1e-3}}; discover them with params_for (--param/-p METHOD:KEY=VALUE on the command line). An unknown method id raises KeyError before any I/O; with dry_run=True a key the method does not accept raises too, naming the accepted ones.
    • dry_run (bool) - return the plan (a DataFrame, see plan) without running anything. Free; do it first.
    • timeout (float | None) - per-method wall-clock cap in seconds; size it from scan's runtime_tier / observed_worst_sec. A method exceeding it is recorded as TIMEOUT and the sweep moves on.
    • skip_existing (bool) - reuse a method's existing output file instead of recomputing (resume an interrupted sweep). Together with params= it raises ValueError - reuse is keyed on the file, not the parameters. Reuse only checks that the file exists, not that it is complete.
    • batch (keyword-only) - one batch id per cell, in the embedding's row order (array-like / Series / CSV path), used for the batch metrics INSTEAD of the default rule (batch = the label FILE each cell came from, cty1.csv -> 1 ...). Recorded as batch_source='user'; a wrong length marks that method RUN_OK_EVAL_FAILED.
    • evaluate (bool) - compute metrics on the outputs (default True); verbose - per-method progress lines.

    BatchResult¶

    What run_all returns (and load_batch reloads).

    • .summary - one row per method, sorted by method name: method, status, run_sec, output_kind, emb_shape, n_tunable, label_order, label_order_confidence, batch_source, n_batches plus one column per metric. status is CHAIN_OK, CHAIN_OK_GRAPH_METHOD, RUN_OK_NO_EMBEDDING, RUN_OK_EVAL_FAILED, TIMEOUT or FAIL; batch_source is file_of_origin (the label-file rule), user (batch= / rescore) or None (single label file).
    • .long - the tidy seven-column metric, value, method, dataset, category, clustering, source frame (source="user"), the input to mtb.plot.bubble; a long.csv written by an earlier release reloads with the two columns filled.
    • .failures - method, status, error for everything that went wrong (always check it).
    • .results - the raw per-method records (status, out_dir, metrics, label_order_candidates), so a sweep's outputs stay addressable.
    • .plot(**kw) - bubble figure of every scored method; keywords go to plot.bubble (metrics=, methods=, order=, title=, save= ...). Raises ValueError if nothing scored.
    • .rescore(*, batch=None, labels=None, only=None, verbose=False) -> BatchResult - re-evaluate the STORED outputs with a different batch vector, labels or metric subset - nothing is re-run; returns a new BatchResult (call .save() to persist it).
    • .save(out_dir=None) -> Path - writes summary.csv, long.csv, failures.csv, batch_result.json (run_all does this automatically).

    mtb.load_batch¶

    mtb.load_batch(out_dir) -> BatchResult

    Reload a BatchResult that run_all / BatchResult.save wrote, to re-plot, re-inspect or rescore without re-running anything.

    mtb.params_for¶

    mtb.params_for(method: str, category: str | None = None, modalities: list[str] | set[str] | None = None, *,
               dataset: str | None = None, data_path: Path | str | None = None) -> dict

    The tunable hyperparameters a method's variant exposes (tunable, with defaults), the defaults the wrapper emits, the effective values a wrapper run uses, fixed_in_script (with file:line) and the upstream knobs the script never exposes. A multi-variant method needs modalities= (or category=) to pick the variant, or dataset= (+ data_path=): then the variant whose input files are all in that folder is chosen, and mtb.AmbiguousVariantError names the modality-sets when none or several are. modalities=["rna", "atac"] selects an atac_gas / atac_peak variant too. An empty tunable means the upstream script hardcodes its settings. multibench params METHOD [--category] [--modalities] [--format table|csv|tsv|json] prints the same per variant (all variants when none is selected).

    mtb.describe_layout¶

    mtb.describe_layout(category: str | None = None) -> str

    How to lay out your OWN dataset so the package can find it: the directory layout and the role -> filename mapping (rna.h5, adt.h5, atac.h5 / peak.h5, cty.csv, numbered rna1.h5 ... per batch), the HDF5 file format (matrix/data features x cells, matrix/features, matrix/barcodes), the ATAC peak-vs-gene-activity warning with the method lists built from the registry at call time, the export_dataset route, and - for cross - the SPATIAL REGISTRATION block (a directory of .h5ad slices). category is validated; 'spatial' raises with a pointer to describe_layout('cross').

    mtb.runtime_hint¶

    mtb.runtime_hint(method: str) -> dict

    What this method has been OBSERVED to cost: {"tier", "worst_sec", "observed"} - tier in fast (<5 min), medium (5-30 min), slow (30 min-2 h), very_slow (>2 h); observed lists the actual measurements on one shared machine as {dataset, cells, sec, source}, where source says where the number came from (manual, summary_csv = the shipped re-run sweeps, verification = the shipped verification table) - the table keeps the longest time recorded per (method, dataset), rounded up, and cells is null where no run recorded the count. A never-measured method returns tier "unknown". Use it to size run_all(timeout=...), not to promise a finish time.

    mtb.sweep¶

    mtb.sweep(dataset: str, category: str, method: str, param: str, values, *,
          out_dir, modalities=None, data_path=None, timeout=None, verbose=True) -> pd.DataFrame

    Run ONE method repeatedly over a range of one hyperparameter, one output directory per value, and return the per-setting metrics with the swept value as a column (a tidy frame goes to <out_dir>/sweep_long.csv, one series per setting, ready for plot.bubble). A failing setting appears with status FAIL / TIMEOUT rather than aborting the sweep.

    Top-level functions¶

    mtb.run¶

    mtb.run(method: str, category: str, task: str = "clustering", *, inputs: dict, out_dir: str,
        params: dict | None = None, convert: bool = True, cmd_template: str | None = None,
        repo_path: Path | None = None) -> RunResult

    Build a method variant's command, preflight its conda env, wrap the command (default "conda run -n {env} {cmd}"), run it in out_dir, and load the typed output. inputs is a {modality_role: path-or-AnnData} dict; non-canonical modality inputs are auto-converted to the canonical scMultiBench .h5 (into <out_dir>/inputs/) unless convert=False. Auxiliary roles (data_dir, source_data, target_data, source_cty, target_cty, out_dir) are passed through verbatim. Returns a RunResult.

    Parameters

    • method (str) - registry method id (KeyError with a did-you-mean hint otherwise).
    • category (str) - one of vertical, diagonal, mosaic, cross; drives variant selection together with the supplied modalities.
    • task (str) - accepted and currently ignored: variant selection depends only on category and the supplied modalities.
    • inputs (dict) - {modality_role: path}, e.g. {"rna": ..., "atac_gas": ...}; the non-auxiliary, non-label roles select the variant. Paths may be relative: every path-valued input is made absolute (symlinks preserved) and a directory role such as data_dir gets its trailing separator before the argv is built, because the method runs with cwd=out_dir.
    • out_dir (str) - working directory; created if missing, made absolute the same way (RunResult.out_dir is the absolute path).
    • params (dict | None) - extra method hyperparameters merged into the command.
    • convert (bool) - convert non-aux inputs to the canonical .h5 (default True).
    • cmd_template (str | None) - command wrapper; None uses the method's env via conda run -n {env} {cmd} and preflights it (OSError naming the install command when the env is missing); a custom template skips the preflight.
    • repo_path (Path | None) - checkout holding tools_scripts/; default auto-provisioned (config.DEFAULT.repo_path).

    mtb.evaluate¶

    mtb.evaluate(output, category: str | None = None, task: str = "clustering", labels=None,
             clustering=None, batch=None, metric_set: str = "scib", slow_metrics: bool = False,
             only=None, *, obsm: str = "X_emb", column: str | None = None,
             label_order: list[str] | None = None, family: str | None = None,
             verbose: bool | None = None) -> pd.DataFrame

    Compute scIB metrics on a run output, returning a metric.csv-shaped frame (index = metric in the canonical spelling load_results uses, single Value column; never empty - a request that selects no metric raises). metric_set="scib" is the only metric set (ValueError otherwise), with task in {clustering, batch, all} (dimension_reduction is served by the clustering group; registration raises NotImplementedError - not wired). ARI, NMI and iF1 need scIB's Leiden resolution sweep: tens of seconds for a few thousand cells, minutes for ~10^4; one stderr line announces it above 2,000 cells (verbose), and clustering= or only= naming metrics that do not need it skips it. Clustering metrics require labels; clustering is optional (omitted -> scIB optimal-resolution Leiden, ten resolutions 0.2-2.0, highest NMI). batch / all additionally require batch - unless labels is a list (or an ordered dict) of two or more files, in which case the file of origin is the batch (the run_all rule). batch= under task="clustering" computes no batch metric and emits a UserWarning. This is re-exported from mtb.eval.evaluate.

    Parameters

    • output - the embedding, cells x dims: numpy.ndarray (dims x cells is auto-transposed against the label count, with a warning), pandas.DataFrame, AnnData (uses .obsm[obsm]), scipy sparse, or a path - .h5 (dataset data, the benchmark's embedding.h5), .h5ad (read as an AnnData, so its obs columns and ids are usable), .npy, .csv / .tsv. A missing path raises FileNotFoundError naming it and the current directory; an .h5 without data raises ValueError listing its keys (and says so when it looks like a canonical INPUT matrix). An AnnData (obs_names) or a DataFrame with a non-default index carries cell ids - see labels.
    • category (str | None) - validated when given (ValueError listing the four); the metrics do not depend on it.
    • task (str) - clustering (default), batch, or all; family (keyword-only) is accepted as an alias with the same clustering / batch vocabulary load_results and recommend use.
    • labels - one cell type per cell in the row order of output: a CSV path (header row; column x / the only column / the last of two behind a barcode index - column= disambiguates), a LIST of CSV paths concatenated in order, a dict from labels_for (one entry, or several in the cell-stacking order labels_for returns; any other order needs label_order=), a 1-D array / Series / Categorical / list, a single-column DataFrame, or - for an AnnData output - an obs column name. Arrays, lists and files are matched POSITIONALLY; a Series / DataFrame with a non-default index is ALIGNED BY CELL ID when output carries ids (AnnData / indexed DataFrame) - missing or extra ids raise ValueError naming the first offenders - and matched positionally with a UserWarning against a bare array (labels.to_numpy() silences it).
    • clustering - optional precomputed cluster assignment (same forms and alignment rule as labels, obs column name for AnnData; an .h5 path is read from /obs/cluster_leiden); skips the Leiden sweep.
    • batch - batch labels, one per cell (same forms and alignment rule; obs column name for AnnData).
    • metric_set (str) - "scib" is the only metric set.
    • slow_metrics (bool) - also compute kBET (shells out to R; hours on large datasets).
    • only - collection of metric names to compute ({"ASW", "cLISI"}); everything else is skipped, including the Leiden sweep when no requested metric needs it (ARI, NMI and iF1 need it; clustering= replaces it for ARI / NMI). Validated against task: a batch metric (ASW_batch, GC, iLISI, kBET) under task="clustering" raises ValueError (GC is a batch metric: pass task="all" (or "batch") and batch=<vector>), a clustering metric under task="batch" raises likewise, kBET needs slow_metrics=True. A bare string raises TypeError; unknown names raise ValueError listing mtb.plot.CLUSTERING_METRICS + mtb.plot.BATCH_METRICS.
    • obsm (str, keyword-only) - .obsm key for AnnData / .h5ad output (default "X_emb"; "X" means .X).
    • column (str | None, keyword-only) - column to take when labels is a CSV / DataFrame with several columns.
    • label_order (list[str] | None, keyword-only) - only for a multi-entry labels dict: its keys in the order the method stacked the cells (numbered files ascending - cty1, cty2, ... - and rna before atac, NOT alphabetical; label_order=list(d) trusts a dict from labels_for). A subset of the keys selects those files; unknown / repeated / empty raise ValueError, label_order with non-dict labels raises TypeError.
    • verbose (bool | None, keyword-only) - None (default) prints the Leiden-sweep notice on stderr only above 2,000 cells; True / False force it on / off.

    Raises ValueError for missing labels / batch, unknown category or metric name, a metric the task cannot produce, length mismatches (input length mismatch: emb has N cells, celltype has M), cell-id mismatches when aligning, ambiguous label files and a multi-entry dict in a non-stacking order without label_order; TypeError for unsupported input types.

    Graceful degradation

    Metrics whose external dependency is unavailable return NaN with a warning rather than failing the call: cLISI / iLISI need scib's compiled LISI helper, which ships as a Linux x86-64 binary - when it cannot run, evaluate rebuilds it in place once with scib's own build line if g++ / c++ / clang++ is on PATH, and only otherwise records NaN (the warning carries the g++ rebuild command); kBET needs R via rpy2 (and slow_metrics=True). All other scIB metrics (ARI, NMI, ASW, iASW, iF1, ASW_batch, GC) compute in pure Python.

    mtb.to_long¶

    mtb.to_long(value_df, method, dataset, category, *, clustering: str = "default",

    mtb.load_results¶

    mtb.load_results(category: str | None = None, task: str | None = None, metric_set: str = "scib",
                 dataset: str | list[str] | None = None, method: str | list[str] | None = None,
                 metric: list[str] | str | None = None, clustering: str = "default",
                 result_path: Path | str | None = None, *, source: str = "published",
                 methods: list[str] | None = None, family: str | None = None) -> pd.DataFrame

    Benchmark metric tables as a tidy long frame with the columns, in this order, metric, value, method, dataset, category, clustering, source. Method ids are canonical registry tokens (MOFA+ -> MOFA2, Seurat(WNN) -> Seurat_WNN) and metric codes canonical (iFI -> iF1). When the default-clustering correction file metric_asw_iasw_if1.csv is present, its corrected ASW / iASW / iF1 values override those in metric.csv.

    Parameters

    • category (str | None) - vertical, diagonal, mosaic, or cross; None loads every category that has tables for source (ValueError on an unknown token).
    • task (str | None) - None / "all" (every metric), "clustering" (ARI, NMI, ASW, iASW, iF1, cLISI) or "batch" (ASW_batch, GC, iLISI, kBET); anything else raises. family (keyword-only) is the same selector under the name recommend and evaluate also accept; an unknown family names the list_tasks() token or dataset id that landed in that slot.
    • metric_set (str) - "scib" is the only metric set (ValueError listing it otherwise).
    • dataset (str | list[str] | None) - dataset id(s); default all of the category. Every element is validated: a dataset with no table raises FileNotFoundError naming the missing ids and the available ones (across both sources for "both").
    • method / methods (str | list[str] | None) - keep only these methods (alias tolerant, case-folded against the registry); an id the registry does not know raises KeyError with a did-you-mean hint, a known method with no rows gives an empty frame plus a UserWarning listing the methods present (and the source that has it). methods= is the list alias; passing both raises.
    • metric (list[str] | str | None) - keep only these metric codes (alias tolerant; same empty-frame rule).
    • clustering (str) - default, louvain, or kmeans (metric.csv / metric_louvain.csv / metric_kmeans.csv). A <method>_louvain result dir is reported under the canonical id with clustering="louvain"; a table kept one level down in a run-configuration folder (MOFA2/filtered3/metric.csv, MOFA2/kmeans/metric_kmeans.csv - cross D53 / D56 / D57) is read too (kbet/ skipped, an ambiguity warned). The re-run sweeps are default only.
    • result_path (Path | str | None) - a results ROOT (holding scib_metric/ and/or rerun/; default the tables shipped in the package) OR a single long CSV file: blank clustering / source cells are filled per row (default / user), source="published" or "both" keeps every row, and any other source value filters on the file's own column (a value the file does not carry raises ValueError listing the ones present).
    • source (str, keyword-only) - "published" (default; the paper's scIB tables - none for mosaic), "rerun" (the package's sweeps rerun/long_all_<dataset>.csv: vertical D11/D11s, diagonal D28/D28s, mosaic D45/D45s, cross D52/D52s; the source column says rerun, the sweep's package version travels in frame.attrs["rerun_version"]), or "both".     Raises FileNotFoundError (no table for the request, with the path looked at and what IS available - mosaic says "use source='rerun'"), ValueError (unknown category / task / clustering / source, or a result_path file without the long-format columns).

    mtb.find_methods¶

    mtb.find_methods(category: str | None = None, task: str | None = None, needs_labels: bool | None = None,
                 atac: str | None = None, modalities: list[str] | set[str] | None = None,
                 runnable: bool | None = None, tunable: bool | None = None, *,
                 available: bool | None = None) -> list[str]

    Return method ids matching every supplied filter. Every token is validated: a typo raises ValueError naming the valid vocabulary instead of silently matching nothing. category, modalities, needs_labels and atac are evaluated per variant: a method matches when ONE of its variants satisfies all of them together - so scMoMaT is listed for find_methods("vertical", modalities=["rna", "adt"], needs_labels=False) (its vertical variant takes no labels, only its mosaic one does) and Multigrate is not listed for find_methods("vertical", modalities=["rna", "atac"]) (its only ATAC-consuming variant is mosaic).

    Parameters

    • category (str | None) - integration category the method must declare.
    • task (str | None) - one of list_tasks.
    • needs_labels (bool | None) - per variant: does the matching variant take a cell-type-label (cty) role as a REQUIRED input (method_info(m)["supports"][i]["needs_labels"]); method_info(m)["needs_labels"] is the any-variant flag.
    • atac (str | None) - exact match on the declared ATAC representation, "peak" or "gene_activity" (aliases "peaks" / "gas") - what the UPSTREAM script expects, which is not always what its role name suggests (moETM / scMM / iPOLNG take role atac_gas but consume peaks); only variants that consume ATAC can satisfy it.
    • modalities (list[str] | set[str] | None) - keep methods that consume ALL of these base modality types (["rna", "atac"]); "protein" is accepted for adt and role tokens (atac_gas, rna1 ...) are reduced to their base type; a bare string raises TypeError showing the list form. Implicitly excludes stub methods without variants. Methods that take a whole directory (data_dir: the four registration methods) cannot be judged and are KEPT with a UserWarning naming them; scBridge's modalities come from the bare filenames it reads (rna, atac).
    • runnable (bool | None) - True: methods with at least one variant; False: only the stubs.
    • tunable (bool | None) - True: only methods exposing at least one hyperparameter on their command line.
    • available (bool | None, keyword-only) - True: only methods a public install can run (method_info(m)["availability"] == "public", GPSA included - it runs through a package driver); False: the one whose script is not published, SPIRAL (benchmark-host-only).

    mtb.method_info¶

    mtb.method_info(method: str, files_dir: Path | str | None = None, *, verbose: bool = False) -> dict

    A flat dict combining the registry spec with the method's provenance. Keys: id, language, categories, tasks, env, atac, needs_labels (the METHOD-level flag: any variant takes a cty role - per variant read supports[i]["needs_labels"]), status (verified = the command template was cross-checked against the upstream entrypoint AND executed end to end on a reference dataset; declared = wired, not run), availability (public - every entrypoint lives in the public scMultiBench repository - or benchmark-host-only - an entrypoint is an absolute path on the benchmark host and is not published: SPIRAL; scan reports it not runnable. GPSA runs through the package driver engine/drivers/run_gpsa.py and is public), setup_hint, variants (distinct upstream entrypoints), driver (package-side wrapper, or None), scripts_url, repo_url, version, reference ({doi, title, authors, journal, year} or None), notes (short summary), supports (per variant: category, modalities, output_kind, n_tunable, needs_labels), params (per variant: defaults, tunable, effective), fixed_in_script, upstream_knobs, upstream_url. env is the conda env run executes in - group_for - e.g. scmb_torch for SCALEX, scmb_cobolt3 for Cobolt. verbose=True adds notes_long (the upstream-knob audit prose; for a host-only method one sentence says why) and verification - the evidence behind status="verified": a list of {dataset, category, status, wall_s, ARI, baseline, verdict, note} read from the shipped multibench/files/final_verification.tsv (None when no run is recorded; also mtb.discover.verification_for(m)).     mtb.inputs_for¶

    mtb.inputs_for(dataset: str, method: str, category: str, modalities: list[str] | set[str] | None = None,
               data_path: Path | str | None = None, check: bool | None = None) -> dict

    Resolve a dataset folder + method to concrete {modality_role: path} input paths. The dataset tree is flat (<data_path>/<dataset>/<file>); each role is resolved to the file actually present - the role token or a known alias (atac_peak -> peak.h5, atac_gas -> atac.h5), falling back to <role>.h5.     • method (str) - registry method id.
    • category (str) - integration category (validated).
    • modalities (list[str] | set[str] | None) - exact modality-set to select a variant (protein accepted for adt).
    • data_path (Path | str | None) - override config.DEFAULT.data_path.
    • check (bool | None) - None (default): return best-effort paths but warn about missing ones; True: raise FileNotFoundError (listing what IS in the folder) and also run the content preflight - matrix orientation (ValueError for a cells x features file), label length (one row per cell of the modality it labels), and the data_dir content check - exactly what scan reports as files_ok / files_reason; False: silent.

    mtb.plot.*¶

    mtb.plot.bubble¶

    mtb.plot.bubble(long_df, *, metrics=None, methods=None, order=None, aggregate="dataset",
                cmap=None, title=None, save=None, show_language=True,
                require_complete=False, overall="rank", na="warn") -> matplotlib.figure.Figure

    Paper-style bubble table of a tidy long results frame: methods are rows (best first), metrics are columns grouped into the benchmark's task families, each family preceded by an Overall bar. A plain function - help(mtb.plot.bubble) shows this signature; mtb.plot.build_table(...) (numbers, a BubbleTable with methods in row order, overall, matrix - the min-max fills, norm is the same frame -, raw, ranks - the per-column max-ranks concatenated over the family blocks in figure order, index == methods, n = best -, blocks, aggregate, overall_basis, datasets, coverage, method_datasets, category, needs_labels and na_cells) and mtb.plot.render(table, cmap=, title=, show_language=) (figure) are the two halves. Circle radius is 0.85 * sqrt(rank / n) with n the methods scored in that column.

    Parameters

    • long_df (pd.DataFrame) - columns method, metric, value at least (what to_long, load_results and BatchResult.long return); dataset is needed for aggregate="summary". Concatenate frames to compare your method with the benchmark's.
    • metrics (list[str] | None) - metric codes to show, drawn in THIS order within each family block; alias tolerant; an unknown code raises ValueError naming the metrics present.
    • methods (list[str] | None) - methods to show (exact / canonical / case-insensitive); unknown -> ValueError with a hint.
    • order (list[str] | None) - row order for the listed methods; unlisted methods follow, best first. Only reorders, never filters; unknown names raise.
    • aggregate (str) - "dataset" (default; raw values, circles; several datasets are averaged per method with a UserWarning and dataset-tagged row labels) or "summary" (within-dataset max-ranks averaged over datasets, bars; a UserWarning lists methods missing from some datasets).
    • cmap (str | None) - colormap overriding the FIRST family's palette (default blues / greens / purples per family).
    • title (str | None), save (str | None) - figure title; fig.savefig(save, bbox_inches="tight"), format by suffix.
    • show_language (bool) - Py / R chip per row (? for methods not in the registry) and an L badge for label-consuming methods, judged by the variants of the FRAME's category (a needs_labels column, as to_long(..., needs_labels=True) writes, is honoured first - inconsistent values for one method raise); a key line under the legends explains the chips (Py / R = language · L = consumes cell-type labels (supervised) · ? = not a registry method).
    • na (str) - what to do when a method lacks a metric: its Overall averages the ranks of the metrics it HAS and that column's ranks count only the methods scored in it; "warn" (default) reports each such method once per build (YukiNet: DR and clustering Overall over 3 of 4 metrics (cLISI n/a), kept as table.na_cells), "skip" is silent, "raise" refuses an incomplete frame.
    • require_complete (bool) - with "summary": restrict to methods present in EVERY dataset (ValueError if none is).
    • overall (str) - "rank" (default: minmax(mean over metrics of max-rank(mean over datasets of within-dataset max-rank)), absence = rank 0) or "mean_overall" (mean over datasets of minmax(mean over metrics of within-dataset max-rank), absence skipped). Pass the same value to plot.bar for the same ordering; the formula in use is printed on the figure.

    Raises ValueError for missing columns (with a hint when the frame looks like evaluate()'s wide output), unknown names, duplicate (method[, dataset], metric) rows (they would be silently averaged), bad aggregate / overall.

    mtb.env.*¶

    Helpers for the conda environments that mtb.run orchestrates. The CLI is the everyday surface - multibench env doctor (what exists / is missing, with the exact install line for the gaps), multibench env plan --category vertical (the envs with their download / disk sizes and a # total), multibench env status (installed? plus a build-difficulty tag), multibench env install --methods X --packed --run (a dry run until --run; --packed downloads prebuilt archives and falls back to the lockfile build). The environments are linux-64 conda envs: mtb.env.host_platform_problem() returns a sentence on any other host (None on Linux), the CLI prints it as a warning: first, and env install --run / create / create-group refuse there unless --force (force=True on install_packed / create_all / create / create_group / create_env; dry runs work everywhere).

    mtb.env.doctor¶

    mtb.env.doctor(category: str | None = None, methods: list[str] | None = None, conda: str | None = None, *,
               as_frame: bool = False) -> list[dict]

    Preflight: per env needed to run the methods, is it present and is a lockfile available to build it - [{env, methods, exists, has_lock}], coverage-sorted (as_frame=True -> a DataFrame). The CLI legend: [x] installed, [L] missing with a lockfile ready, [!] missing and no lockfile, then the multibench env install ... line for the gaps.

    mtb.env.plan¶

    mtb.env.plan(category: str | None = None, methods: list[str] | None = None, *, as_frame: bool = False) -> list[dict]

    Which envs to build to cover a set of methods - [{env, shared, methods, availability}], one entry per distinct env listing the methods it serves (build these few envs instead of one per method); availability is benchmark-host-only when every method the env serves needs an unpublished script - only SPIRAL's spiral_environment today (the env builds, the method still cannot run off the benchmark host) - else public. mtb.env.packed_sizes() returns the shipped size snapshot (multibench/engine/packed_sizes.json: {env: {archive_bytes, unpacked_bytes}}, None = not measured; 3 of 29 archives measured so far, regenerated by tools/packed_sizes.py) that env plan / env install --packed print as dl / disk with a # total (? for the unmeasured). mtb.env.status(as_frame=) is behind env status; its difficulty vocabulary lives in mtb.env.DIFFICULTY (easy, old-scvi, old-tensorflow, R, verified, blocked-script, unknown) and the * mark in mtb.env.VERIFIED_STAR. mtb.env.create_all(category, methods, dry_run=True) is the one-shot provisioning call behind env install.

    mtb.env.group_for¶

    mtb.env.group_for(method: str) -> str

    Return the conda env a method runs and provisions in: the explicit per-method name from env_groups.yaml (Matilda -> "matilda"), else its shared group env (SCALEX -> "scmb_torch", Cobolt -> "scmb_cobolt3", the R methods -> "scmb_r"), else its own scmb_<method> env (own_env_name). This is the {env} the default cmd_template fills, the env column of scan, and the same value as mtb.method_info(...)["env"].

    mtb.env.default_env_name¶

    mtb.env.default_env_name(method: str) -> str
mtb.env.own_env_name(method: str) -> str

    default_env_name is the env name EVERY entry point uses for the method - identical to group_for - so scan, run, env doctor / plan / install / create and env recipe / env yml all agree (multibench env recipe Matilda names matilda); KeyError with a did-you-mean hint for an unknown id. own_env_name is the method's own singleton name, scmb_<method>, which earlier releases returned from default_env_name even for grouped methods (so env recipe Matilda named an env nothing else expected).

    RunResult¶

    mtb.run returns a RunResult dataclass. Its fields:

    • method (str) - the method id that was run.
    • out_dir (Path) - the working directory the command ran in.
    • cmd (list[str]) - the fully wrapped argv that was executed (incl. the conda run prefix).
    • output - the loaded primary output (e.g. the joint embedding ndarray; may be dims x cells - evaluate re-orients it).
    • extra (dict) - {file: loaded_output} for any declared extra outputs.
    • stdout (str) / stderr (str) - captured streams.

    A failed run (non-zero exit) raises RuntimeError with the tail of stderr/stdout rather than returning a RunResult; a missing conda env raises OSError before anything is written.
