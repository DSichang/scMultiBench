    API reference¶

    The scMultiBench API (imported as multibench, aliased throughout the docs as mtb) exposes a small, flat, free-function API organised into a handful of namespaces:

    • mtb.* - the top-level surface: the benchmark workflow (scan, run_all, describe_layout), run one method, evaluate an output, to_long to reshape it, stored results (load_results, results_coverage, recommend), and discovery helpers (list_methods, find_methods, method_info, cite, inputs_for, labels_for). mtb.__all__ is exactly this surface (dir(mtb) shows nothing else); the 0.2.1 spellings are listed under Deprecated in 0.3.0.
    • mtb.plot.* - scIB-style figures (bubble, bar, build_table).
    • mtb.eval.* - the evaluation pipeline (evaluate, to_long).
    • mtb.io.* - the canonical-format adapter (export_dataset, to_canonical, read_canonical, normalize_peak_names).
    • mtb.data.* - fetch the reference datasets.
    • mtb.catalog.* - typed views of the benchmark's metadata tables.
    • mtb.config.* - resolved paths (Config, DEFAULT).
    • mtb.env.* - per-method conda environments: status, plan, install, doctor, recipe.

    The end-to-end story: mtb.io.export_dataset writes your data as a dataset folder, mtb.scan says which methods can run on it, mtb.run_all runs and scores them into a BatchResult whose .long frame - the same tidy frame mtb.load_results returns for the stored benchmark - goes into mtb.plot.bubble. Underneath, mtb.run returns a RunResult whose output flows into mtb.evaluate, and mtb.to_long reshapes that into the same long frame. The same story from the shell:

    terminal
    multibench layout vertical                         # how to lay out MY data
multibench convert my.h5ad data/MYCITE --rna X --adt obsm:protein --labels obs:celltype
multibench scan MYCITE --category vertical --data-path data
multibench params Matilda                          # the hyperparameters --param accepts, per variant
multibench run --method Matilda --category vertical --input rna=... --out-dir runs/Matilda
multibench evaluate --output runs/Matilda/embedding.h5 --labels data/MYCITE/cty.csv \
    --method Matilda --dataset MYCITE --category vertical --out runs/Matilda/long.csv
multibench plot bubble --category vertical --dataset D11 --out fig.pdf
multibench plot bubble --input runs/Matilda/long.csv --category vertical --dataset D11 --out fig.pdf   # overlay
multibench cite Matilda MOFA2

    Every subcommand wraps exactly one Python function with the same flag names; multibench <command> --help documents every flag. Tables, ids and commands go to stdout; progress ([run_all] ...), # dry run notes, warning: ... and error: ... go to stderr, so 2>/dev/null silences the chatter. scan and run-all --dry-run print the same frame as a compact table (method, modalities, runnable, files_ok, env_ok, runtime_tier, reason, long text clipped to 80 chars); --columns all or --format csv|tsv|json gives every column unclipped, command included - the exact command line run() would execute per variant whose inputs resolve (paths absolutized, exactly as run passes them; run-all --dry-run also lists them under the table). run --dry-run prints the one command (mtb.run(..., dry_run=True)), --param/-p METHOD:KEY=VALUE (KEY=VALUE on run) sets hyperparameters and params METHOD lists them per variant with the values the script pins. evaluate --metrics takes a family token or a comma list (--only is a hidden deprecated alias that prints warning: --only is deprecated since 0.3.0; use --metrics on stderr). plot --input is repeatable and, together with --category, overlays your rows on the stored table; convert takes --category (the ATAC filename rule) and copies an already-canonical .h5 instead of re-encoding it. The env commands are dry runs until --run, print a warning: ... linux-64 line on a non-Linux host, and env install --run refuses there unless --force. Exit codes: 0 ok, 1 a runtime error (error: ... on stderr; MULTIBENCH_DEBUG=1 shows the traceback), 2 a usage error.

    Method environments

    Running a method shells out to the conda environment it shares with other compatible tools via conda run -n <env> <cmd>, where <env> is mtb.method_info(method)["env"] - the same env multibench env install / mtb.env.install provisions (overridable through cmd_template). The original method scripts are never modified - multibench only builds the command, converts inputs to the canonical .h5, and loads the typed output.

    Error vocabulary

    Every entry point validates its tokens the same way: an unknown method id raises KeyError with a did-you-mean hint; an unknown category, task, atac or modality token raises ValueError listing the valid values; a bare string where a list of ids / tokens is expected (methods="StabMap", modalities="rna") raises TypeError showing the list form; a missing dataset folder or file raises FileNotFoundError listing the folders that exist (or the path and the current directory); a method with several variants that neither modalities= nor the folder's files single out raises mtb.AmbiguousVariantError - a ValueError that also matches KeyError, listing the modality-sets and the folder's contents; a missing conda env raises OSError naming the install command. Warnings are UserWarnings, one of them a subclass you can filter on: mtb.DegenerateRerunWarning (a re-run row that most likely failed silently). Nothing silently returns an empty result.

    Benchmark workflow¶

    The four category tutorials are built on these functions.

    mtb.scan¶

    mtb.scan(dataset: str, category: str | None = None, *, methods: list[str] | None = None,
         modalities: list[str] | None = None, data_path: Path | str | None = None,
         out_dir="<out_dir>", params: dict | None = None, verbose: bool = True) -> pd.DataFrame

    Report every method that can run on dataset, why the rest cannot, and the exact command each one would run - the frame run_all(..., dry_run=True) returns (identical, pinned by a test) and multibench scan / run-all --dry-run print. One row per (method, category, modalities) variant, runnable rows first, with two independent gates:

    • files_ok / files_reason - the input files resolve on disk, are oriented features x cells, every label CSV has one row per cell of the modality it labels, and a data_dir method finds what it needs (>= 2 .h5ad slices with obsm['spatial'] for registration). This gate always runs, whether or not any conda env is installed - a laptop without environments still tells you whether your layout is right.
    • env_ok / env_reason - the method's conda env exists on this machine; the reason names the env and the one-method install command.

    runnable = files_ok & env_ok; reason joins the non-empty reasons (empty iff runnable) in a SHORT form - the exception class, the method/dataset/category: prefix and the absolute directory are dropped (input files not found on disk: {'atac': 'atac.h5'}. Available files in D11: [...]), while files_reason / env_reason keep the verbatim text with full paths. Further columns: modalities (a +-joined string here, e.g. "rna+adt"; run_all / inputs_for take a list - split on "+"; "(data_dir)" marks a method that consumes a whole directory), env, output_kind, n_tunable, needs_labels (does this variant demand a label file), atac ('peak' / 'gene_activity' / None), runtime_tier / observed_worst_sec (measured, see method_info(m)["runtime"] under method_info), caveat (known content traps: an ATAC role resolved to the wrong representation in either direction - a peak matrix fed to a gene-activity method, or a non-peak matrix fed to a peak method - judged per role from method_info(m)["atac"]) and command - the exact shell line run() would execute for that variant, built with run(..., dry_run=True) (paths absolutized exactly as run passes them; the empty string for a row whose inputs do not resolve). The frame has 18 columns: method, category, modalities, env, output_kind, n_tunable, runtime_tier, observed_worst_sec, caveat, runnable, reason, files_ok, files_reason, env_ok, env_reason, needs_labels, atac, command. The one method whose script is not published - SPIRAL, method_info(m)["availability"] == "benchmark-host-only" - fails the file gate with files_reason benchmark-host-only: script not published: .... GPSA ships as a package driver and is public. Nothing is executed and nothing is fetched or written.

    >>> sc = mtb.scan("D11", "vertical")
[scan] files OK for 14/25 method rows; 0/25 envs installed
>>> sc.columns.tolist()
['method', 'category', 'modalities', 'env', 'output_kind', 'n_tunable', 'runtime_tier',
 'observed_worst_sec', 'caveat', 'runnable', 'reason', 'files_ok', 'files_reason',
 'env_ok', 'env_reason', 'needs_labels', 'atac', 'command']
>>> sc.command.iloc[0]
"conda run -n scmb_concerto python .../tools_scripts/Concerto/main_Concerto.py --path1 .../D11/rna.h5 --path2 .../D11/adt.h5 --save_path '.../<out_dir>/Concerto_D11/'"

    Parameters

    • dataset (str) - folder NAME under data_path (not a path); a missing folder raises FileNotFoundError listing the folders that do exist.
    • category (str | None) - restrict to one category (ValueError on a typo); default all four.
    • methods (list[str] | None, keyword-only) - restrict to these ids (KeyError with a hint on a typo; a bare string raises TypeError); blocked rows are kept with their reason. Never empty: ValueError (no <category> variant matches ...) when no variant of the requested methods exists under category.
    • modalities (list[str] | None, keyword-only) - restrict to one modality combination (["rna", "adt"]; protein accepted for adt; a bare string raises TypeError). An exact selector, so directory-input variants ("(data_dir)") are excluded by any non-empty list - a UserWarning names them and says modalities=[] selects exactly them.
    • data_path (Path | str | None, keyword-only) - the folder that CONTAINS dataset; default the configured data root.
    • out_dir (keyword-only) - the output directory the command lines name; the default is the literal placeholder <out_dir>, so a preview needs no directory - pass the real one for paste-ready lines.
    • params (dict | None, keyword-only) - per-method hyperparameters merged into the command lines ({"Matilda": {"epochs": 5}}); a key the method does not accept raises KeyError naming the accepted ones.
    • verbose (bool) - print [scan] files OK for k/n method rows; e/n envs installed (default True; the CLI passes False).

    mtb.run_all¶

    mtb.run_all(dataset: str, category: str, out_dir=None, *, methods=None, modalities=None,
            params: dict | None = None, data_path=None, evaluate: bool = True,
            dry_run: bool = False, verbose: bool = True, timeout: float | None = None,
            skip_existing: bool = False, batch=None) -> BatchResult | pd.DataFrame

    Run every method that scan marks runnable (or the methods= subset) on dataset end to end - inputs, the method's own conda env, output loading, metrics - and collect everything in a BatchResult. A method that fails becomes a row in .failures, never an exception. When nothing is runnable the ValueError lists one line per requested variant with its own reason (or the first 3 of N blocked variants when methods= was not given); a requested method with no variant in the category raises scan's no <category> variant matches ....

    Parameters

    • dataset / data_path - as in scan.
    • out_dir - one sub-directory per method. Required for a real run (TypeError: run_all() needs out_dir= for a real run (dry_run=True returns the scan frame without one)); may be omitted with dry_run=True.
    • methods (list[str] | None) - restrict to these ids (KeyError + hint on a typo).
    • modalities (list[str] | None) - restrict to ONE modality combination, e.g. ["rna", "atac_gas"] (gene activity) vs ["rna", "atac_peak"] (peaks). The two ATAC representations do NOT map to the obvious filenames - see describe_layout.
    • params (dict | None) - per-method hyperparameters, {"Cobolt": {"lr": 1e-3}}; discover them with params_for (--param/-p METHOD:KEY=VALUE on the command line). An unknown method id raises KeyError before any I/O; with dry_run=True a key the method does not accept raises too, naming the accepted ones (a real run records it as that method's FAIL row).
    • dry_run (bool) - return scan(...) for the same selection - the identical frame, command column included - without running anything. Free; do it first.
    • timeout (float | None) - per-method wall-clock cap in seconds; size it from scan's runtime_tier / observed_worst_sec. A method exceeding it is recorded as TIMEOUT and the sweep moves on.
    • skip_existing (bool) - reuse a method's existing output file instead of recomputing (resume an interrupted sweep). Together with params= it raises ValueError - reuse is keyed on the file, not the parameters. Reuse only checks that the file exists, not that it is complete.
    • batch (keyword-only) - one batch id per cell, in the embedding's row order (array-like / Series / CSV path), used for the batch metrics INSTEAD of the default rule (batch = the label FILE each cell came from, cty1.csv -> 1 ...). Recorded as batch_source='user'; a wrong length marks that method RUN_OK_EVAL_FAILED.
    • evaluate (bool) - compute metrics on the outputs (default True); verbose - per-method progress lines.

    BatchResult¶

    What run_all returns (and load_batch reloads).

    • .summary - one row per method, sorted by method name: method, status, run_sec, output_kind, emb_shape, n_tunable, label_order, label_order_confidence, batch_source, n_batches plus one column per metric. status is CHAIN_OK, CHAIN_OK_GRAPH_METHOD, RUN_OK_NO_EMBEDDING, RUN_OK_EVAL_FAILED, TIMEOUT or FAIL; batch_source is file_of_origin (the label-file rule), user (batch= / rescore) or None (single label file).
    • .long - the tidy seven-column metric, value, method, dataset, category, clustering, source frame (source="user"), the input to mtb.plot.bubble; a long.csv written by an earlier release reloads with the two columns filled.
    • .failures - method, status, error for everything that went wrong (always check it).
    • .results - the raw per-method records (status, out_dir, metrics, label_order_candidates), so a sweep's outputs stay addressable.
    • .plot(**kw) - bubble figure of every scored method; keywords go to plot.bubble (metrics=, methods=, order=, title=, save= ...). Raises ValueError if nothing scored.
    • .rescore(*, batch=None, labels=None, metrics=None, verbose=False) -> BatchResult - re-evaluate the STORED outputs with a different batch vector, labels or metric selection (metrics= as in evaluate) - nothing is re-run; returns a new BatchResult (call .save() to persist it).
    • .save(out_dir=None) -> Path - writes summary.csv, long.csv, failures.csv, batch_result.json (run_all does this automatically).

    mtb.load_batch¶

    mtb.load_batch(out_dir) -> BatchResult

    Reload a BatchResult that run_all / BatchResult.save wrote, to re-plot, re-inspect or rescore without re-running anything.

    mtb.params_for¶

    mtb.params_for(method: str, category: str | None = None, modalities: list[str] | set[str] | None = None, *,
               dataset: str | None = None, data_path: Path | str | None = None) -> dict

    The tunable hyperparameters a method's variant exposes (tunable, with defaults), the defaults the wrapper emits, the effective values a wrapper run uses, fixed_in_script (with file:line) and the upstream knobs the script never exposes. A multi-variant method needs modalities= (or category=) to pick the variant, or dataset= (+ data_path=): then the variant whose input files are all in that folder is chosen, and mtb.AmbiguousVariantError names the modality-sets when none or several are. modalities=["rna", "atac"] selects an atac_gas / atac_peak variant too. An empty tunable means the upstream script hardcodes its settings. multibench params METHOD [--category] [--modalities] [--format table|csv|tsv|json] prints the same per variant (all variants when none is selected).

    mtb.describe_layout¶

    mtb.describe_layout(category: str | None = None) -> str

    How to lay out your OWN dataset so the package can find it: the directory layout and the role -> filename mapping (rna.h5, adt.h5, atac.h5 / peak.h5, cty.csv, numbered rna1.h5 ... per batch), the HDF5 file format (matrix/data features x cells, matrix/features, matrix/barcodes), the ATAC peak-vs-gene-activity warning with the method lists built from the registry at call time, the export_dataset route, and - for cross - the SPATIAL REGISTRATION block (a directory of .h5ad slices). category is validated; 'spatial' raises with a pointer to describe_layout('cross').

    mtb.sweep¶

    mtb.sweep(dataset: str, category: str, method: str, param: str, values, *,
          out_dir, modalities=None, data_path=None, timeout=None, verbose=True) -> pd.DataFrame

    Run ONE method repeatedly over a range of one hyperparameter, one output directory per value, and return the per-setting metrics with the swept value as a column (a tidy frame goes to <out_dir>/sweep_long.csv, one series per setting, ready for plot.bubble). A failing setting appears with status FAIL / TIMEOUT rather than aborting the sweep.

    Top-level functions¶

    mtb.run¶

    mtb.run(method: str, category: str, *, inputs: dict, out_dir: str, params: dict | None = None,
        task: str | None = None, convert: bool = True, cmd_template: str | None = None,
        repo_path: Path | None = None, dry_run: bool = False) -> RunResult | list[str]

    Build a method variant's command, preflight its conda env, wrap the command (default "conda run -n {env} {cmd}"), run it in out_dir, and load the typed output. inputs is a {modality_role: path-or-AnnData} dict; non-canonical modality inputs are auto-converted to the canonical scMultiBench .h5 (into <out_dir>/inputs/) unless convert=False. Auxiliary roles (data_dir, source_data, target_data, source_cty, target_cty, out_dir) are passed through verbatim. Returns a RunResult, or the argv list with dry_run=True.

    Parameters

    • method (str) - registry method id (KeyError with a did-you-mean hint otherwise).
    • category (str) - one of vertical, diagonal, mosaic, cross; drives variant selection together with the supplied modalities. Everything after it is keyword-only (a third positional argument raises TypeError).
    • inputs (dict) - {modality_role: path}, e.g. {"rna": ..., "atac_gas": ...}; the non-auxiliary, non-label roles select the variant. Paths may be relative: every path-valued input is made absolute (symlinks preserved) and a directory role such as data_dir gets its trailing separator before the argv is built, because the method runs with cwd=out_dir.
    • out_dir (str) - working directory; created if missing, made absolute the same way (RunResult.out_dir is the absolute path).
    • params (dict | None) - extra method hyperparameters merged into the command.
    • task (str | None) - accepted and currently ignored: variant selection depends only on category and the supplied modalities.
    • convert (bool) - convert non-aux inputs to the canonical .h5 (default True).
    • cmd_template (str | None) - command wrapper; None uses the method's env via conda run -n {env} {cmd} and preflights it (OSError naming the install command when the env is missing); a custom template skips the preflight.
    • repo_path (Path | None) - checkout holding tools_scripts/; default auto-provisioned (config.DEFAULT.repo_path).
    • dry_run (bool) - return the wrapped argv (a list[str]) that a real call would execute - inputs absolutized as above, the checkout located but never fetched, nothing created or written, no env preflight. The form behind multibench run --dry-run and scan's command column.
    >>> mtb.run("Matilda", "vertical", inputs=mtb.inputs_for("D11", "vertical", "Matilda"),
...         out_dir="out/Matilda", dry_run=True)[:6]
['conda', 'run', '-n', 'matilda', 'python', '.../multibench/engine/drivers/run_matilda.py']

    mtb.evaluate¶

    mtb.evaluate(output, labels=None, *, category: str | None = None, batch=None, metrics=None,
             clustering=None, obsm: str = "X_emb", label_order=None, verbose: bool = True) -> pd.DataFrame

    Compute scIB metrics on a run output, returning a metric.csv-shaped frame (index = metric in the canonical spelling load_results uses, single Value column; never empty - a request that selects no metric raises). metrics= is the one selection knob (see the metrics= vocabulary): None computes every applicable metric - the clustering family, plus the batch family whenever a batch vector exists. ARI, NMI and iF1 need scIB's Leiden resolution sweep: tens of seconds for a few thousand cells, minutes for ~10^4; one stderr line announces it above 2,000 cells (verbose), and clustering= or a metrics=[...] list naming only metrics that do not need it skips it. Clustering metrics require labels; clustering is optional (omitted -> scIB optimal-resolution Leiden, ten resolutions 0.2-2.0, highest NMI). The batch family requires batch - unless labels is a list (or an ordered dict) of two or more files, in which case the file of origin is the batch (the run_all rule). batch= under metrics="clustering" computes no batch metric and emits a UserWarning. Everything after labels is keyword-only (the 0.2 positional evaluate(output, category, ...) raises TypeError). This is re-exported from mtb.eval.evaluate.

    Parameters

    • output - the embedding, cells x dims: numpy.ndarray (dims x cells is auto-transposed against the label count, with a warning), pandas.DataFrame, AnnData (uses .obsm[obsm]), scipy sparse, or a path - .h5 (dataset data, the benchmark's embedding.h5), .h5ad (read as an AnnData, so its obs columns and ids are usable), .npy, .csv / .tsv. A missing path raises FileNotFoundError naming it and the current directory; an .h5 without data raises ValueError listing its keys (and says so when it looks like a canonical INPUT matrix). An AnnData (obs_names) or a DataFrame with a non-default index carries cell ids - see labels.
    • labels - one cell type per cell in the row order of output: a CSV path (header row; column x / the only column / the last of two behind a barcode index; a file with several columns is ambiguous - pass the column itself, pd.read_csv(p)["col"]), a LIST of CSV paths concatenated in order, a dict from labels_for (one entry, or several in the cell-stacking order labels_for returns; any other order needs label_order=), a 1-D array / Series / Categorical / list, a single-column DataFrame, or - for an AnnData output - an obs column name. Arrays, lists and files are matched POSITIONALLY; a Series / DataFrame with a non-default index is ALIGNED BY CELL ID when output carries ids (AnnData / indexed DataFrame) - missing or extra ids raise ValueError naming the first offenders - and matched positionally with a UserWarning against a bare array (labels.to_numpy() silences it).
    • category (str | None) - validated when given (ValueError listing the four); the metrics do not depend on it.
    • batch - batch labels, one per cell (same forms and alignment rule; obs column name for AnnData).
    • metrics - None (every applicable metric) | "clustering" | "batch" | "all" | a list of metric codes. A list computes exactly those (alias tolerant, ["ari", "nmi"] -> ARI, NMI) and skips everything else, including the Leiden sweep when no listed metric needs it (ARI, NMI and iF1 need it; clustering= replaces it for ARI / NMI); kBET is computed only when named in a list (R via rpy2; hours on large datasets). "all" or "batch" without a batch vector raises ValueError (batch labels required for metrics='all' ...: pass batch=<vector>, or metrics='clustering'), as does a listed batch metric; a bare code (metrics="ARI"), a list_tasks() token ("imputation"), an unknown code or an empty list raise ValueError naming the valid vocabulary.
    • clustering - optional precomputed cluster assignment (same forms and alignment rule as labels, obs column name for AnnData; an .h5 path is read from /obs/cluster_leiden); skips the Leiden sweep.
    • obsm (str) - .obsm key for AnnData / .h5ad output (default "X_emb"; "X" means .X).
    • label_order (list[str] | None) - only for a multi-entry labels dict: its keys in the order the method stacked the cells (numbered files ascending - cty1, cty2, ... - and rna before atac, NOT alphabetical; label_order=list(d) trusts a dict from labels_for). A subset of the keys selects those files; unknown / repeated / empty raise ValueError, label_order with non-dict labels raises TypeError.
    • verbose (bool) - True (default) prints the Leiden-sweep notice on stderr above 2,000 cells; False never prints.

    Raises ValueError for missing labels / batch, unknown category or metric name, length mismatches (input length mismatch: emb has N cells, celltype has M), cell-id mismatches when aligning, ambiguous label files and a multi-entry dict in a non-stacking order without label_order; TypeError for unsupported input types and for the removed 0.2 keywords (see Deprecated in 0.3.0).

    >>> mtb.evaluate(emb, labels).index.tolist()                      # single batch: the clustering family
['ARI', 'NMI', 'ASW', 'iASW', 'iF1', 'cLISI']

    Graceful degradation

    Metrics whose external dependency is unavailable return NaN with a warning rather than failing the call: cLISI / iLISI need scib's compiled LISI helper, which ships as a Linux x86-64 binary - when it cannot run, evaluate rebuilds it in place once with scib's own build line if g++ / c++ / clang++ is on PATH, and only otherwise records NaN (the warning carries the g++ rebuild command); kBET needs R via rpy2 (and is computed only when metrics=[...] names it). All other scIB metrics (ARI, NMI, ASW, iASW, iF1, ASW_batch, GC) compute in pure Python.

    The metrics= vocabulary¶

    evaluate, load_results, recommend and BatchResult.rescore share one metric selector, parsed in one place:

    metrics= selects
    None (default) every metric available / applicable: for evaluate, the clustering family plus the batch family when a batch vector exists; for load_results, every metric in the tables; for recommend, the clustering family
    "clustering" ARI, NMI, ASW, iASW, iF1, cLISI (mtb.plot.CLUSTERING_METRICS)
    "batch" ASW_batch, GC, iLISI, kBET (mtb.plot.BATCH_METRICS)
    "all" both families (evaluate then needs a batch vector)
    a list of codes exactly those, alias tolerant (["ari", "nmi"]); evaluate computes kBET only this way

    A bare code (metrics="ARI") raises ValueError pointing at the list form; a mtb.list_tasks() token ("imputation", "dimension_reduction") raises explaining that the slot selects a metric family; an unknown code raises listing the valid ones (['ARI', 'NMI', 'ASW', 'iASW', 'iF1', 'cLISI', 'ASW_batch', 'GC', 'iLISI', 'kBET', 'PCR']). It replaces the 0.2 task=, family=, only= and slow_metrics= keywords.

    Write an AnnData / MuData as a canonical benchmark dataset folder - rna.h5, adt.h5, atac_peak.h5 (+ a hard-linked atac.h5) or atac_gas.h5, and cty.csv - so that mtb.scan(name, data_path=dataset_dir.parent) and run_all work on your own data. rna / adt / atac take a selector string - 'X', 'obsm:<key>', 'layer:<key>', 'mod:<name>' (MuData; optionally 'mod:<name>.obsm:<key>') - OR an object: an AnnData, a DataFrame or a 2-D array; labels / batch take a selector or a Series / sequence. When data is a MuData the bare modality NAME works too (rna="rna", atac="atac" = mdata.mod[name].X) and labels / batch accept '<mod>:<obs column>' (labels="rna:celltype") - what the 0.2 from_mudata did:

    mtb.io.export_dataset(mdata, "data/MYMULTIOME", rna="rna", atac="atac", atac_kind="peak",
                      labels="rna:celltype", category="vertical")   # -> rna.h5, atac.h5, cty.csv

    Every modality is re-indexed to one master obs_names order (that of data), and a modality whose barcode set differs raises ValueError (all modalities of one dataset must cover the same cells). ADT feature names come from the DataFrame columns / AnnData var_names / uns["<obsm key>_names"]; a bare array falls back to feature_0.. with a UserWarning - pass adt_names=[...]. None skips the modality. atac_kind is required with atac: 'peak' (chr:start-end features) or 'gene_activity' (-> atac_gas.h5 only, so the gene-activity role never silently falls back to a peak matrix); a warning is raised when the feature names contradict the declared kind. labels is 'obs:<col>' (or 'mod:<name>.obs:<col>') -> cty.csv (header x); batch (same grammar) splits the cells per batch value and writes the numbered rna1.h5 / adt1.h5 / cty1.csv ... layout instead. category (keyword-only) fixes the ATAC filename for the layout you target: "vertical" writes plain atac.h5 for BOTH atac_kind values - the vertical (paired multiome) methods read the atac role and never atac_peak.h5 / atac_gas.h5; the representation is recorded nowhere on disk, so feed the one method_info(m)["atac"] wants; "diagonal" / "mosaic" / "cross" keep atac_peak.h5 / atac_gas.h5 (no atac.h5 link); None keeps today's names. All matrices are cells x features and written transposed; sparse matrices are streamed. Returns dataset_dir.

    mtb.io.to_canonical¶

    mtb.io.to_canonical(src, out: Path | str | None = None, modality: str | None = None, convert: bool = True, *,
                    layer: str | None = None, obsm: str | None = None, mod: str | None = None,
                    dtype: str = "float64", compression: str | None = "gzip", block: int = 1024,
                    category: str | None = None, feature_names: list | None = None) -> Path

    Convert src to a canonical .h5 and return its path. src is an AnnData, a MuData (mod= required), or a path to .h5ad / .h5mu / .csv / .tsv (cells x features) / .loom / a canonical .h5 (passed through untouched). out is the output file, or an existing directory when modality is given - then the canonical filename (rna.h5, adt.h5, atac_peak.h5, atac_gas.h5, atac.h5) is appended. modality (rna | adt | atac | atac_peak | atac_gas; aliases protein, peak, gas / gene_activity) is validated, warns when ATAC feature names contradict the role, and with modality='adt' on an AnnData that has obsm keys requires obsm= / layer= to say where the protein matrix is. category="vertical" (keyword-only) makes an ATAC role write plain atac.h5 whatever the representation - the file the vertical methods read (to_canonical(atac, d, modality="peak") alone writes atac_peak.h5, which no vertical variant opens); the other categories and None keep atac_peak.h5 / atac_gas.h5 / atac.h5. feature_names= overrides the feature names written to matrix/features. convert=False means "never write" (non-canonical input raises). A missing src path raises FileNotFoundError naming the path and the current directory; an .h5 without matrix/data raises ValueError listing the keys it found (and flags a top-level data as a method OUTPUT, not an input). Sparse matrices are streamed without densifying, but matrix/data is stored dense (features x cells x 8 B uncompressed): above mtb.io.DENSE_WARN_BYTES (1 GB) a UserWarning states the size and the two mitigations - filter to HVGs / informative peaks first, or dtype='float32', which halves it.

    mtb.env.*¶

    Helpers for the conda environments that mtb.run orchestrates - mtb.env.__all__ is status, plan, install, doctor, recipe, each behind the multibench env subcommand of the same name; everything else in the module is CLI plumbing (importable, not advertised). The CLI is the everyday surface - multibench env doctor (what exists / is missing, with the exact install line for the gaps), multibench env plan --category vertical (the envs with their download / disk sizes and a # total), multibench env status (installed? plus a build-difficulty tag), multibench env install --methods X --packed --run (a dry run until --run; --packed downloads prebuilt archives and falls back to the lockfile build). The environments are linux-64 conda envs: on any other host the CLI prints a warning: ... linux-64 ... line first and env install --run refuses unless --force (force=True on mtb.env.install); dry runs work everywhere.

    mtb.env.install¶

    mtb.env.install(methods: list[str] | None = None, *, category: str | None = None,
                packed: bool = True, dry_run: bool = True, conda: str | None = None,
                force: bool = False) -> list[dict]

    The Python face of multibench env install (the CLI calls this function). Builds the install plan for the selection - methods and/or category, neither = the whole benchmark - and returns one dict per env: {env, methods, exists, has_lock, cmds, state, packed_url, archive_bytes, unpacked_bytes}, where cmds are the argv lists a lockfile build runs. dry_run=True (default) returns the plan and creates nothing - state is have, packed archive published (an archive exists; packed_url / archive_bytes say which and how big), no archive - lockfile build, build(dry-run) (packed=False), or NO-LOCK; dry_run=False installs - the packed archive when packed and one is published (falling back to the lockfile build when the download fails), the lockfile build otherwise - and state becomes PACKED, BUILD, have or NO-LOCK.     RunResult¶

    mtb.run returns a RunResult dataclass. Its fields:

    • method (str) - the method id that was run.
    • out_dir (Path) - the working directory the command ran in.
    • cmd (list[str]) - the fully wrapped argv that was executed (incl. the conda run prefix).
    • output - the loaded primary output (e.g. the joint embedding ndarray; may be dims x cells - evaluate re-orients it).
    • extra (dict) - {file: loaded_output} for any declared extra outputs.
    • stdout (str) / stderr (str) - captured streams.

    A failed run (non-zero exit) raises RuntimeError with the tail of stderr/stdout rather than returning a RunResult; a missing conda env raises OSError before anything is written.
