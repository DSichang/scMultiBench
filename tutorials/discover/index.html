    Discover methods¶

    scMultiBench's registry holds 40 methods across four integration categories - the 40 benchmark methods, several of them registered for more than one scenario. Before you run anything, the discovery API answers the only question that matters at the start of a project: given the data I have and the task I care about, which methods can I actually use?

    This page is pure metadata lookup - no method environments, no GPUs, no data on disk. Everything here is a fast, in-process query against the registry and the benchmark catalog.

    TL;DR

    import multibench as mtb

mtb.list_tasks()                     # ['batch', 'classification', 'clustering', ...]
mtb.list_methods(category="vertical")        # every method in a category
mtb.find_methods(category="diagonal",        # filter by what your data has
                 modalities=["rna", "atac"],
                 needs_labels=False)
mtb.method_info("SCALEX")            # env, atac kind, label needs, availability, reference, variants
mtb.recommend("vertical", modalities=["rna", "adt"])   # ranked from stored results
mtb.inputs_for("D28", "SCALEX", "diagonal")  # resolve benchmark input paths
print(mtb.cite(["SCALEX"]))          # BibTeX for the benchmark + the method

    The four integration categories¶

    Every method declares one or more categories describing the experimental design it integrates. Pick the row that matches your data, then filter within it.

    Category Design Typical modalities
    vertical Paired, the same cells measured in several modalities RNA+ADT, RNA+ATAC, RNA+ADT+ATAC
    diagonal Unpaired, separate cells per modality, bridged by shared features RNA batch + ATAC batch
    mosaic Overlapping modalities tied together by a bridge dataset mixed, partially paired
    cross Several fully matched datasets integrated together replicate cohorts (and spatial slices)

    Category is the first filter

    A method written for paired CITE-seq (vertical) cannot consume an unpaired RNA + ATAC design (diagonal). Always pass category= first, it is the single largest constraint on what is applicable.

    List what exists¶

    mtb.list_tasks() returns the sorted set of tasks declared across the registry, and mtb.list_methods() returns method ids, optionally narrowed by category and/or task.

    import multibench as mtb

mtb.list_tasks()
# ['batch', 'classification', 'clustering', 'dimension_reduction', 'imputation', 'registration']

mtb.list_methods()                       # all 40 registry methods
mtb.list_methods(category="vertical")    # only paired-design methods
mtb.list_methods(category="diagonal", task="clustering")

    Both arguments are AND-combined: a method is returned only if it declares the requested category and the requested task. A method's categories are derived from its variants (method_info(m)["supports"]), never declared separately, so list_methods(category=c), find_methods(category=c) and env plan --category c always agree: 18 vertical, 14 diagonal, 6 mosaic and 12 cross methods.

    Filter by what your data has¶

    mtb.list_methods filters on category and task only. When you want to filter by the shape of your data - which modalities you measured, how your ATAC is encoded, whether you have cell-type labels to supervise with - use mtb.find_methods:

    mtb.find_methods(category: str | None = None, task: str | None = None,
                 needs_labels: bool | None = None, atac: str | None = None,
                 modalities: list[str] | set[str] | None = None,
                 runnable: bool | None = None, tunable: bool | None = None, *,
                 available: bool | None = None) -> list[str]

    A worked example - I have an unpaired RNA batch and an ATAC batch, I have no cell-type annotation, and I want a method that consumes both modalities:

    mtb.find_methods(
    category="diagonal",
    modalities=["rna", "atac"],
    needs_labels=False,
)
# ['SCALEX', 'Portal', 'uniPort', ...]

    How the filters combine

    find_methods returns the methods matching all supplied filters; passing None (the default) disables a filter. category, modalities, needs_labels and atac are judged per variant: a method matches when one of its variants satisfies all four together, not when different variants satisfy different ones. So scMoMaT is listed for find_methods("vertical", modalities=["rna", "adt"], needs_labels=False) - its vertical variant takes no labels, only its mosaic one does - and Multigrate is not listed for find_methods("vertical", modalities=["rna", "atac"]), because its only ATAC-consuming variant is mosaic. modalities is a subset test on the matching variant - the modality types it consumes must be a superset of what you ask for, so ["rna"] is broad and ["rna", "atac"] is stricter. Role tokens are reduced to their base type ("atac_gas" means "atac", "rna1" means "rna") and "protein" is accepted for "adt". Every token is validated: a typo in category, task, atac or a modality raises ValueError naming the valid vocabulary instead of silently matching nothing, and a bare string where a list is expected (modalities="rna") raises TypeError with the list form. Methods that consume a whole directory (the four spatial registration methods) cannot be judged by modalities=: they are kept under any such filter with a UserWarning naming them (task= "registration" selects them); scBridge's modalities are derived from the bare filenames it reads (rna, atac).

    The atac filter is about encoding, not presence: methods that consume ATAC do so either as a gene-activity matrix (atac="gene_activity", alias "gas") or as raw peaks (atac="peak", alias "peaks"). It is the representation the upstream script expects, which is not always what its role name suggests (moETM, scMM and iPOLNG take a role called atac_gas but consume peaks). If your ATAC is already summarised to gene activities, filter for it so you do not pick a peak-only method.

    mtb.find_methods(category="diagonal", atac="gene_activity")
mtb.find_methods(category="vertical", tunable=True)     # methods whose command line exposes a hyperparameter

    needs_labels is derived from the variants' roles - a variant "needs labels" when it takes a cell-type-label (cty) file as a required input. The filter is per variant; method_info(m)["needs_labels"] is the any-variant flag (scMoMaT is True because of its mosaic variant) and method_info(m)["supports"][i]["needs_labels"] the per-variant answer.

    available=True keeps the methods a public install can run; available=False lists the one whose script is not published - SPIRAL (method_info(m)["availability"] == "benchmark-host-only"; scan reports it not runnable with the reason benchmark-host-only: script not published). GPSA runs through a package driver (method_info("GPSA")["driver"]) and is public, like PASTE and PASTE2; all three registration methods are public:

    mtb.find_methods(task="registration", available=True)   # ['GPSA', 'PASTE', 'PASTE2']

    Inspect a single method¶

    mtb.method_info returns a flat dict combining the registry spec with the method's provenance (upstream reference, repository, version, a one-line summary) and optional catalog metadata. It is the fastest way to understand a method before you commit to running it.

    mtb.method_info("SCALEX")
# {'id': 'SCALEX', 'language': 'python', 'categories': ['diagonal'],
#  'tasks': ['clustering', 'batch'], 'env': 'scmb_torch', 'atac': 'gene_activity',
#  'needs_labels': False, 'status': 'verified', 'availability': 'public', 'setup_hint': '',
#  'variants': ['tools_scripts/SCALEX/main_SCALEX.py'], 'driver': None,
#  'repo_url': 'https://github.com/jsxlei/SCALEX', 'version': '1.0.2',
#  'reference': {'doi': '10.1038/s41467-022-33758-z', 'title': 'Online single-cell data integration ...',
#                'authors': 'Xiong L, ...', 'journal': 'Nature Communications', 'year': 2022},
#  'notes': 'Online integration of heterogeneous single-cell datasets ... no labels needed.',
#  'supports': [{'category': 'diagonal', 'modalities': ['rna', 'atac_gas'],
#                'output_kind': 'embedding', 'n_tunable': 0, 'needs_labels': False}],
#  'params': {...}, 'fixed_in_script': {...}, 'upstream_knobs': {...}, 'upstream_url': '...'}
    Field Meaning
    id canonical registry token (the name you pass to run)
    language python or r, determines the conda env conventions
    categories / tasks integration categories the method supports / tasks its output is scored on
    env conda env name; run orchestrates via conda run -n <env>
    atac "gene_activity", "peak", or None if it consumes no ATAC
    needs_labels derived, any-variant: does some variant take a label file as a required input? (supports[i]["needs_labels"] per variant)
    status verified = the command template was cross-checked against the upstream entrypoint and the method was executed end to end on a reference dataset (declared = wired, not run)
    availability public - every entrypoint is in the public scMultiBench repository, or a package driver (GPSA); benchmark-host-only - the entrypoint is an absolute path on the benchmark host, not published (SPIRAL; scan reports it not runnable)
    variants / supports the per-design entrypoints, and per variant: category, modalities, output kind, n_tunable, needs_labels
    reference, repo_url, version, notes upstream provenance (verbose=True adds notes_long, the upstream-knob audit prose, and verification)
    verification (verbose=True) the evidence behind status="verified": one {dataset, category, status, wall_s, ARI, baseline, verdict, note} per recorded run, from the shipped multibench/files/final_verification.tsv (status there is the run outcome - CHAIN_OK, CHAIN_OK_GRAPH_METHOD, RUN_OK_NO_EMBEDDING; verdict is DRIFT when a re-run left the ARI tolerance)
    params per variant: defaults, tunable, effective (what the wrapper emits)

    Pass files_dir= to enrich the dict with catalog columns (deep_learning, output) joined from the published benchmark tables:

    mtb.method_info("SCALEX", files_dir="multibench/files")
# adds: 'deep_learning': 'Yes', 'output': 'embedding'

    mtb.runtime_hint(method) adds what the method has been observed to cost ({"tier", "worst_sec", "observed": [{dataset, cells, sec, source}, ...]}) - the measurements behind scan()'s runtime_tier column. Each observation says where it came from (source: manual, summary_csv = the shipped re-run sweeps, verification = the shipped verification table); the table keeps the longest recorded time per (method, dataset), and cells is null where no run recorded the count. An unknown method id raises KeyError with a did-you-mean hint in every one of these functions; mtb.cite("SCALEX", "GLUE") takes ids one per argument (or one list), like the CLI. For a benchmark dataset, mtb.inputs_for(dataset, method, category) returns absolute paths and, when a method has several variants for the category, picks the one whose files are in the folder (mtb.params_for(method, dataset=...) does the same for the hyperparameter table; when none or several fit, both raise mtb.AmbiguousVariantError, a ValueError).

    Rank from stored results¶

    mtb.recommend turns the shipped metric tables into a ranking for a category, with coverage made explicit - a method scored on 1 of 22 datasets is not a winner:

    mtb.recommend("vertical", modalities=["rna", "adt"])
#   method  grand_score  n_datasets  n_datasets_total  coverage  needs_labels  runtime_tier  worst_sec ...

    needs_labels there follows the category's variants (scMoMaT is False in a vertical ranking), as does the L badge of the bubble plot.

    source="rerun" ranks the package's own re-run sweeps instead of the paper's tables; long_df=pd.concat([published, mine]) places your own method in the same ranking; family="batch" (or task="batch") ranks on the batch-correction metrics. Nothing is hidden: every method wired for the category (find_methods(task=..., modalities=..., runnable=True)) that has no rows in the chosen source is appended with grand_score NaN, n_datasets 0 and coverage 0.0 after the scored rows, and ONE UserWarning lists the datasets dropped for having fewer than min_methods methods, the partial coverage, and the unscored methods (try source="rerun" when that source has them). The choices the ranking was made under travel with the frame as df.attrs (family, task, source, not_scored, missing) - pandas keeps .attrs through .copy() and column selection but most concat / merge operations drop them, so the NaN rows themselves are the robust signal.

    The full benchmark catalog¶

    mtb.catalog.* exposes the benchmark metadata as tidy DataFrames, useful when you want the whole picture rather than a single lookup.

    from multibench import catalog

catalog.methods()    # one row per method: language, deep_learning, atac, output,
                     # needs_labels, categories, tasks (registry-derived), + canonical_id
catalog.datasets()   # one row per dataset: dataset, simulated, category, has_results, ...
catalog.metrics()    # the metric-details table

    catalog.datasets() is the union of the paper's dataset table (63 real + 8 simulated, 71 ids) and every dataset id that has a stored result table - 80 rows today, the extra nine being ids that exist only as result tables (the D11s / D28s / D45s / D52s re-run subsamples, D24, SD7-SD10); category and has_results are filled from the shipped result tree at call time, and the simulated flag (set for ids beginning SD) separates the simulations:

    ds = catalog.datasets()
ds[~ds["simulated"]]    # real datasets only

    Two helpers normalise the catalog's free-text spellings to canonical tokens:

    catalog.canonical_id("Seurat v5")     # 'Seurat_v5'
catalog.canonical_id("scipenn")       # 'sciPENN' - case-folded against the registry
catalog.canonical_metric("kbet")      # 'kBET'
catalog.known_metrics()               # the ten scIB codes + 'PCR'

    An unknown name comes back unchanged; canonical_id(name, strict=True) raises KeyError with a did-you-mean hint instead (what load_results uses).

    Which method should I use?¶

    A practical decision path tied to the four categories:

    1. Start from your design. Paired cells -> category="vertical"; unpaired modalities bridged by features -> "diagonal"; partially overlapping with a bridge -> "mosaic"; replicate matched datasets -> "cross".
    2. Filter by data shape. find_methods(category=..., modalities=[...], atac=..., needs_labels=...) - drop methods that need labels you do not have, or an ATAC encoding you cannot provide.
    3. Rank what is left. recommend(category, modalities=[...]) orders the candidates from stored results and shows the runtime tier next to the score.
    4. Check your folder. mtb.scan("MYDATA", category) reports, per method, whether the files are right (files_ok) and whether its environment is installed (env_ok) - then run_all.
    candidates = mtb.find_methods(category="diagonal", modalities=["rna", "atac"],
                              needs_labels=False)
mtb.recommend("diagonal", modalities=["rna", "atac"])[["method", "grand_score", "coverage", "runtime_tier"]]
