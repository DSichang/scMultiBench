    Load & plot results¶

    scMultiBench ships the published benchmark metric tables from Liu, Ding et al. (Nature Methods 2025) and the package's own re-run sweeps, alongside the code that drew the figures. This tutorial covers the two functions you need to turn those tables into a publication-ready panel: mtb.load_results reads the stored metric tables into one tidy long frame, and mtb.plot.bubble renders the scIB-style bubble table the paper uses.

    TL;DR

    import multibench as mtb

df = mtb.load_results("vertical", dataset="D11")                  # the paper's table
fig = mtb.plot.bubble(df, metrics=["ARI", "NMI", "ASW", "cLISI"],
                      title="Vertical integration, D11", save="d11.pdf")

    The same panel from the shell:

    terminal
    multibench plot bubble --category vertical --dataset D11 \
    --metrics ARI,NMI,ASW,cLISI --out d11.pdf

    Step 1, Load a tidy results frame¶

    mtb.load_results walks the stored result tree and returns a single long-format pandas.DataFrame with seven columns - metric, value, method, dataset, category, clustering, source. One row per (method, dataset, metric) cell. This is the shape every downstream function (plot.bubble, plot.bar, recommend, your own groupby/pivot) expects.

    import multibench as mtb

df = mtb.load_results(
    category="vertical",      # vertical | diagonal | mosaic | cross; None -> every category
    task=None,                # None/"all" -> every metric; "clustering" / "batch" -> one family
    metric_set="scib",        # only "scib" is wired in v1
    dataset="D11",            # None -> every dataset; a list -> several
    method=None,              # None -> every method present; a name or list (alias tolerant)
    metric=None,              # None -> every metric; or ["ARI", "NMI"]
    clustering="default",     # default | louvain | kmeans
    source="published",       # published | rerun | both
)
df.head()
#   metric     value      method dataset  category clustering     source
# 0    NMI  0.792936  Multigrate     D11  vertical    default  published
# 1    ARI  0.759446  Multigrate     D11  vertical    default  published
# 2    ASW  0.656011  Multigrate     D11  vertical    default  published
# ...

    Category tokens¶

    scMultiBench groups its 40 integration methods into four integration categories. Pass the clean token; the loader maps it to the (space-named) folder on disk for you. A typo raises ValueError listing the valid ones.

    Token Integration setting Modalities
    vertical Paired, the same cells profiled in every modality RNA+ADT, RNA+ATAC, RNA+ADT+ATAC
    diagonal Unpaired, separate batches bridged by shared features RNA batch + ATAC batch
    mosaic Overlapping modalities joined through a bridge mixed
    cross Several fully-matched datasets integrated together matched

    Published vs re-run tables¶

    Two sources ship in the package, and the source column of every frame says which one a row came from:

    source= What it is Datasets
    "published" (default) the paper's scIB tables (multibench/result/scib_metric/) vertical 23, diagonal 18, cross 7 (D52-D54, D56-D59; tables kept one level down in a run-configuration folder such as MOFA2/filtered3/ are read too); none for mosaic (FileNotFoundError pointing at source="rerun")
    "rerun" the package's own sweeps - every wired method at default settings, the tables behind the category tutorials (multibench/result/rerun/long_all_<dataset>.csv, source="rerun-0.2.1") vertical D11/D11s, diagonal D28/D28s, mosaic D45/D45s, cross D52/D52s
    "both" the concatenation tell them apart by source

    The two can differ for the same method and dataset: methods are stochastic, the published sweep ran on other hardware, and the published tables are partial (vertical ships 8 of the paper's methods; cross mostly one method per dataset) while the re-runs cover every wired method for their dataset. Cite the published numbers; use the re-runs to check reproducibility and to compare against your own run, and compare ranks rather than decimals (see Are my numbers comparable?). mtb.results_coverage(category) lists which (dataset, method, clustering, source) combinations exist; mtb.available_datasets(category, source=...) lists the loadable dataset ids.

    cov = mtb.results_coverage("cross")
cov[cov.dataset == "D52"].groupby("source").method.nunique()   # published 1, rerun-0.2.1 8

    Clustering variants¶

    scIB clustering metrics depend on the upstream clustering. The published tree stores up to three variants per (dataset, method); pick one with clustering=:

    Value Reads Meaning
    "default" metric.csv the paper's default clustering (Leiden), with corrected ASW/iASW/iF1 coalesced in
    "louvain" metric_louvain.csv Louvain re-clustering
    "kmeans" metric_kmeans.csv k-means re-clustering

    Which variants ship, per category

    diagonal ships all three variants for all 18 datasets. vertical ships louvain for a single (dataset, method) pair (D3 / Concerto) and no kmeans; cross ships louvain and kmeans for D56 only (MOFA2, from its nested filtered3/metric_louvain.csv and kmeans/metric_kmeans.csv). Asking for a variant that is not there raises FileNotFoundError naming the file it looked for; point result_path= at a tree that contains it, or keep clustering="default". The re-run sweeps are default only. A result directory named <method>_louvain is reported under the method's canonical id with clustering="louvain" - no method id ever ends in _louvain.

    Metric names and method ids are canonicalised

    Both metric= and the returned metric column are passed through catalog.canonical_metric, so you can filter with the clean scIB names - ARI, NMI, ASW, iASW, iF1, cLISI (clustering) and ASW_batch, GC, iLISI, kBET (batch) - regardless of how the underlying CSV spelled them; mtb.evaluate emits the same spelling, so a to_long frame concatenates with a stored table without duplicate metric columns. Likewise method= accepts any alias of a method id ("mofa+" -> MOFA2, "Seurat(WNN)" -> Seurat_WNN). A filter that matches nothing returns an empty frame with a UserWarning listing what is present, so concatenating several calls never breaks on one typo.

    These are stored tables, not a live run

    To score your own run instead, compute metrics with mtb.evaluate and reshape the wide frame with mtb.to_long(value_df, method, dataset, category) - it emits the same long frame, so it drops straight into plot.bubble next to a stored table. result_path= also accepts a single long CSV (one you saved with to_csv, or a run_all output's long.csv) and reads it back with source="user" unless the file carries its own.

    Step 2, Render the scIB bubble table¶

    mtb.plot.bubble takes the long frame and draws the scIB-style bubble table - the grid of circles the paper uses to rank methods. It returns a matplotlib.Figure.

    fig = mtb.plot.bubble(
    df,
    metrics=["ARI", "NMI", "ASW", "cLISI"],   # column order, left to right (within each family)
    methods=None,                              # None -> every method in df; unknown names raise
    order=None,                                # None -> best first; a list pins those rows on top
    aggregate="dataset",                       # "dataset" | "summary"
    cmap=None,                                 # override the first family's colour ramp
    title="Vertical integration, D11",
    save="d11_bubble.pdf",                     # also returns the Figure
    show_language=True,                        # Py / R chip per row, 'L' badge for label-consuming methods
    require_complete=False,                    # summary: keep only methods present in every dataset
    overall="rank",                            # how the across-dataset Overall is formed (see below)
)

    How to read it:

    • Each row is a method, each column a metric. Metrics are grouped into the paper's task families - blues for DR & clustering, greens for batch correction - and each family is led by an Overall bar. Rows are ordered by the mean of the family Overall scores, best at the top.
    • Circle fill ~ value - darker = higher, on a per-column min-max scale.
    • Circle radius ~ rank - bigger = better in that column (0.85 * sqrt(rank / n); ties take the maximum rank, matching the original R ties.method="max").
    • The family Overall bar - within one dataset, minmax(mean over the family's metrics of per-metric max-rank); length and fill both carry it.
    • Legend - a Score colour ramp per family always; the Rank circle-size legend only under aggregate="dataset" (summary panels draw bars); a dash marks a metric that was not computed for that method (n/a).
    • A ? chip marks a method that is not in the registry (your own), an L badge a method that consumes cell-type labels - supervised, so its scores are not comparable with the unsupervised rows.

    Individual vs. summary panels¶

    The aggregate argument decides what a row's numbers mean.

    # one dataset -> raw metric values are plotted directly
df = mtb.load_results("vertical", dataset="D11")
fig = mtb.plot.bubble(df, metrics=["ARI", "NMI", "ASW", "cLISI"])

    The default. Fill encodes the actual metric value for that dataset. If the frame happens to hold several datasets, values are averaged per (method, metric) first, a UserWarning says so, and the row labels carry the dataset ids.

    # all vertical datasets -> rank within each, then average ranks
df = mtb.load_results("vertical")          # no dataset= -> all
fig = mtb.plot.bubble(df, metrics=["ARI", "NMI", "ASW", "cLISI"],
                      aggregate="summary", require_complete=True,
                      title="Vertical integration, summary")

    Ranks methods within each dataset per metric, then averages those ranks across datasets and draws them as bars - the cross-dataset leaderboard, not a raw mean of incommensurable scores. A method absent from a dataset scores rank 0 there (the paper's rule), which pulls it down; a UserWarning lists such methods, and require_complete=True restricts the panel to methods present in every dataset instead.

    The across-dataset Overall: overall=

    Two formulas exist and they can order methods differently on the same frame. "rank" (bubble's default, the paper's summary rule): minmax(mean over metrics of max-rank(mean over datasets of within-dataset max-rank)) - absence counts as rank 0. "mean_overall" (bar's default): mean over datasets of minmax(mean over metrics of within-dataset max-rank) - each dataset gets its own min-max-scaled overall, averaged over the datasets the method was actually run on (absence skipped). Pass the same overall= to plot.bubble and plot.bar to get the same ordering; the formula in use is printed on the figure.

    Pinning the row order

    Pass order=[...] (a list of method ids) to put those rows first, in that order - handy when you want a fixed method order shared across several figures; unlisted methods follow, best first. order= only reorders (an unknown name raises ValueError); methods=[...] subsets the frame before anything is ranked, and metrics= sets the column order within each family. Duplicate (method[, dataset], metric) rows raise rather than being silently averaged - name variants distinctly.

    Audit the numbers before drawing¶

    mtb.plot.build_table(df, ...) returns the BubbleTable behind the figure (methods in row order, overall, matrix, raw, norm, ranks, blocks), so ranks can be read programmatically - e.g. the position of your own method: mtb.plot.build_table(allruns).methods.index("MyMethod") + 1. mtb.plot.render(table) draws it.

    Summary bars¶

    mtb.plot.bar(df, group="clustering" | "batch", overall=..., top=N, save=...) draws one bar per method with its across-dataset Overall - the benchmark's two summary panels - with one dot per dataset behind each bar (under overall="mean_overall") so a uniformly good method is distinguishable from one that wins a single dataset.

    A concrete example, a vertical panel¶

    Reproduce one vertical-integration panel end to end, then add your own method:

    reproduce_d11.py
    import pandas as pd
import multibench as mtb

# 1. stored table for one dataset - the re-run sweep covers every wired method
bench = mtb.load_results("vertical", dataset="D11", source="rerun")

# 2. your own run, scored with the same metrics (see Evaluate a run)
mine = mtb.to_long(mtb.evaluate(emb, labels=mtb.labels_for("D11")["cty"]),
                   method="MyMethod", dataset="D11", category="vertical")

# 3. bubble table, four clustering metrics, saved to PDF
fig = mtb.plot.bubble(
    pd.concat([bench, mine]),
    metrics=["ARI", "NMI", "ASW", "cLISI"],
    title="Vertical integration, D11 + MyMethod",
    save="d11_vertical.pdf",
)
print(mtb.plot.build_table(pd.concat([bench, mine])).methods.index("MyMethod") + 1)   # its rank

    The returned fig is a plain matplotlib.Figure, so you can keep tweaking it (fig.axes[0]...), embed it in a multi-panel layout, or re-save at another DPI.

    CLI equivalent¶

    The same figure without writing any Python:

    terminal
    multibench plot bubble \
    --category vertical --dataset D11 --source rerun \
    --metrics ARI,NMI,ASW,cLISI \
    --out d11_vertical.pdf

    multibench plot accepts --aggregate dataset|summary, --overall rank|mean_overall, --require-complete, --methods, --title, --input long.csv (your own long table, or a run_all output directory, instead of --category), bar with --group clustering|batch, and writes whatever format --out's extension implies (.pdf, .png, ...). It calls load_results and plot.bubble / plot.bar under the hood, so the result is identical to the script above.

    Visual fidelity

    The bubble table is a matplotlib reproduction of scIB's original R tables (helpers.R / scIB_knit_table.R). The numeric encoding - min-max fills, max-rank radii, the overall bars - is ported verbatim, so rankings and shadings match; the rendering is visually faithful within tolerance rather than a pixel-exact clone of the R figure.
