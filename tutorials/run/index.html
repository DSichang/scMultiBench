    Run a method¶

    mtb.run runs one method on your inputs in the method's own environment and returns its output. Install that environment first (next section). mtb.run_all runs and scores every method that fits a dataset, as in the category tutorials.

    import multibench as mtb

mtb.data.fetch("D28")                  # 137 MB; skipped when already present
res = mtb.run(
    "SCALEX", "diagonal",
    inputs=mtb.inputs_for("D28", "diagonal", "SCALEX"),
    out_dir="runs/scalex_d28",
)
res.output.shape                       # (11014, 10): cells x latent dimensions
    Details

    What a call does. run picks the method variant that matches category and the roles in inputs, converts the inputs to the canonical .h5 format and runs the method's script with out_dir as the working directory. It then loads the output.

    Paths. Relative paths are fine: run makes the inputs and out_dir absolute before it starts.

    Preview. mtb.run(..., dry_run=True) returns the command line without running anything or creating files. multibench run ... --dry-run prints it for a job script; mtb.scan(...)["command"] shows it per method.

    Install the method's environment¶

    Each method runs in its own Linux environment, which must be installed before the first run (on macOS and Windows only dry runs work). multibench env doctor lists what is installed and what is missing.

    multibench env install --methods SCALEX --packed --run

    mtb.method_info("SCALEX")["env"]                # 'scmb_torch'
mtb.env.install(["SCALEX"], dry_run=False)      # the same install from Python
    Details

    Missing environment. When other environments are installed, run raises OSError naming the install command before anything is written.

    No environment and no conda. On such a host run cannot check and fails with FileNotFoundError for conda. Run multibench env doctor.

    Prebuilt archives. --packed downloads a prebuilt environment instead of building one.

    What run returns¶

    res is a RunResult. res.output is the method's main output, here the joint embedding as an array.

    res.output            # numpy array, shape (11014, 10)
res.extra             # other declared outputs, keyed by filename ({} for SCALEX)
res.cmd               # the command line that ran
res.out_dir           # absolute path of the run folder

    Score the embedding with the dataset's label files, then see Evaluate a run:

    metrics = mtb.evaluate(res.output, labels=mtb.labels_for("D28", "diagonal", "SCALEX"),
                       category="diagonal", metrics="all")
    Details

    Other fields. res.method is the method id; res.stdout and res.stderr hold the method's captured output.

    Failed runs. A method that exits with an error raises RuntimeError with the end of its output.

    Label order. With category and method, mtb.labels_for lists the files in the order that method stacks its cells, and evaluate takes the dict as is. Without them it uses the default order: RNA before ATAC, cty1, cty2, ....

    Methods with another order include uniPort (ATAC first), StabMap in cross (its reference batch first) and SMILE and MultiVI in mosaic. A wrong order gives wrong scores without an error; run_all records each method's order in summary.label_order.

    Your own dict. A dict you build or reorder yourself goes in as is only in the default order; name any other order with label_order=.

    Batches. With two or more label files, each cell's file is its batch for the batch metrics.

    Inputs¶

    inputs maps each modality role to a file path or an in-memory AnnData. method_info(m)["supports"] lists the roles each variant expects; for a dataset folder, mtb.inputs_for builds the dict.

    mtb.method_info("SCALEX")["supports"]
# [{'category': 'diagonal', 'modalities': ['rna', 'atac_gas'], 'output_kind': 'embedding',
#   'n_tunable': 0, 'needs_labels': False, 'labels': []}]

mtb.run(
    "SCALEX", "diagonal",
    inputs={"rna": "data/D28/rna.h5", "atac_gas": "data/D28/atac_gas.h5"},
    out_dir="runs/scalex_d28",
)
    Details

    No matching variant. Inputs whose roles match no variant raise KeyError listing the variants the method has. Rename the inputs keys to fix it.

    No or several variants fit. For a method with several variants, inputs_for raises mtb.AmbiguousVariantError when the folder holds the files for none or more than one of them. Pass modalities=; ["rna", "atac"] also matches an atac_gas or atac_peak variant.

    Checking files. inputs_for(..., check=True) raises when a file is missing, a matrix is transposed or a label file has the wrong number of rows.

    Formats. These are converted for you (see to_canonical):

    • .h5ad files
    • .csv / .tsv (cells x features) and .loom files
    • in-memory AnnData
    • canonical .h5 files, passed through unchanged

    MuData. A .h5mu path raises ValueError. Pass each modality as an AnnData (mdata["rna"]), or convert it first with mtb.io.to_canonical(src, out, mod="rna").

    Disk size. The canonical matrix is stored dense, so filter to highly variable genes or informative peaks first. Converting yourself with mtb.io.to_canonical(..., dtype="float32") halves the size.

    No conversion. mtb.run(..., convert=False) passes your paths to the method unchanged.

    Your own data as a dataset folder¶

    mtb.io.export_dataset writes an AnnData or MuData as a dataset folder that scan, run_all and inputs_for read. mtb.describe_layout(category) prints the expected files.

    import anndata as ad
a = ad.read_h5ad("my_citeseq.h5ad")     # X = RNA, obsm['protein'] = ADT
mtb.io.export_dataset(a, "data/MYCITE", rna="X", adt="obsm:protein", labels="obs:celltype")
mtb.io.export_dataset(mdata, "data/MYMULTIOME", rna="rna", atac="atac", atac_kind="peak",
                      labels="rna:celltype", category="vertical")   # from a MuData
mtb.scan("MYCITE", "vertical", data_path="data")    # files_ok / env_ok per method
    Details

    Batches. batch="obs:sample" writes one file per batch (rna1.h5, adt1.h5, cty1.csv, ...).

    One file at a time. mtb.io.to_canonical(src, "data/MYDIAG/", modality="rna") writes one modality under its canonical filename; keep the trailing / when the folder does not exist yet. mtb.io.read_canonical reads a file back as an AnnData.

    Label files. A one-column CSV: a header line x, then one label per cell, e.g. pd.Series(labels, name="x").to_csv(path, index=False).

    ATAC: peaks or gene activity. Say which one the matrix holds (atac_kind=). Each method expects one of the two (method_info(m)["atac"]), and the wrong one runs without an error.

    ATAC file names. With category="vertical" the file is atac.h5, whatever it holds, so write the representation the method expects. Other categories keep atac_peak.h5 / atac_gas.h5.

    Checks. scan's caveat column flags an ATAC file that looks like the wrong representation. inputs_for and scan name the other ATAC file when the expected one is missing.

    GPU or CPU?¶

    Most methods also run without a GPU, only slower. Six need an NVIDIA GPU: on a host without one, run refuses them with OSError before starting, and scan / run_all mark them not runnable.

    >>> [m for m in mtb.list_methods() if mtb.method_info(m)["requires_gpu"]]
['scBridge', 'moETM', 'SMILE', 'sciCAN', 'UnitedNet', 'iPOLNG']
>>> mtb.method_info("scJoint")["cpu_params"]
{'use_cuda': ''}
    Details

    CPU switches. scJoint and scMDC use CUDA unless told otherwise. On a host without a GPU, run adds the flags in method_info(m)["cpu_params"] and prints one line to stderr. A key you pass in params wins.

    Environment builds. The torch environments of the tutorial methods also come as smaller CPU-only builds, which mtb.env.install picks on a host without a GPU. See Archive flavours.

    How the environment is entered: prefix and conda modes¶

    run activates the installed environment folder directly, so no conda binary is needed. When no folder exists but conda is installed, it uses conda run -n <env> instead. MULTIBENCH_RUN_MODE=conda|prefix forces one mode.

    Details

    Where environments live. In <envs_dir>/<env>, where multibench env install --packed --run unpacks them. envs_dir defaults to MULTIBENCH_ENVS_DIR when set; the other defaults are listed under Config.

    Prefix mode. The command runs under bash -c after setting CONDA_PREFIX, putting <prefix>/bin first on PATH and sourcing <prefix>/etc/conda/activate.d/*.sh.

    Forced prefix mode. MULTIBENCH_RUN_MODE=prefix with no environment folder raises OSError naming envs_dir.

    Choosing a cmd_template¶

    Pass cmd_template to run the command another way, for example in a container. {cmd} stands for the built command. You then manage the environment yourself: run skips its environment check.

    mtb.run(..., cmd_template="conda run -n scmb_torch {cmd}")

    mtb.run(..., cmd_template="singularity exec multibench.sif {cmd}")

    mtb.run(..., cmd_template="{cmd}")   # no wrapper: the active interpreter
    Details

    Placement. Put {cmd} last: the rest of the template is placed in front of the command.

    Method scripts. repo_path= points at your own checkout of the scMultiBench method scripts. By default the package fetches one on the first run.

    Reading other output kinds¶

    res.output is a numpy array for every method. Predicted labels (Matilda, scBridge, UnitedNet, Seurat_v3) come back in res.extra as lists of strings.

    Details

    Kinds. method_info(m)["supports"] gives each variant's output_kind: embedding or graph.

    Extra outputs. res.extra maps each extra file name to its content: an array for an embedding or a graph, a list of strings for predicted labels.

    Graph methods. MIRA, scMoMaT and Seurat_WNN return a cell graph, not an embedding, so embedding metrics such as ASW do not apply to res.output.

    Graph methods in run_all. It scores scMoMaT through the UMAP embedding scMoMaT also writes, and records MIRA and Seurat_WNN as RUN_OK_NO_EMBEDDING.
