    Diagonal integration: [multiple RNA, multiple ATAC]¶

    Diagonal integration combines RNA and ATAC measured in different cells, with no pairing between them. This tutorial is for data in several batches: three RNA batches and three ATAC batches. It runs iNMF and online_iNMF on D37mini, 3,000 RNA and 3,000 ATAC profiles of the benchmark dataset D37, then on data in your own format.

    iNMF, online_iNMF and scJoint read ATAC as gene-activity scores, made beforehand with a tool such as Signac or ArchR. GLUE reads the peak matrix. The dataset holds both.

    Methods run on Linux. On macOS or Windows, open this notebook in Colab.

    1. Install¶

    This cell installs multibench-sc. It keeps the numpy and pandas that are already installed, so Colab needs no restart.

    Details

    On Colab, choose a GPU runtime before you run the notebook: Runtime -> Change runtime type -> T4 GPU. On a CPU runtime, an environment that has a smaller CPU build gets that build, and training methods run slower.

    Details

    state is PACKED for an environment downloaded now and have for one that was already there. With dry_run=True, mtb.env.install downloads nothing and returns the plan with its sizes.

    Environments go to mtb.config.envs_dir. To use another disk, set it before this cell.

    3. Run the methods¶

    run runs each method on D37mini and scores its output with the scIB metrics and the classification scores (OCA, ACA, Spec, Sens, F1). res.summary has one row per method with its status, run time and scores. Higher is better for every metric.

    Details

    Each method writes an embedding: a table of numbers with one row per cell. run scores it against the cell-type labels of D37mini.

    The clustering metrics ARI, NMI, ASW, iASW, iF1 and cLISI measure how well the embedding separates the cell types. The batch metrics ASW_batch, ARI_batch, NMI_batch, GC and iLISI measure how well the batches mix. They appear only when the data has several batches.

    The reason column of res.summary says why a method failed. params={"Method": {"key": value}} sets a method's parameters, and mtb.params_for lists them. Many methods take none.

    mtb.load_run("out/D37mini") reloads these results later without running anything.

    4. Plot¶

    res.plot() draws the scores as a bubble table. Circle size shows the rank within a column, and bigger is better. The fill compares a value with the other rows in the same column.

    Details

    The lightest fill is the lowest value in this figure, not zero.

    Metrics are grouped by family: blue for clustering, green for batch correction, pink for classification. Each family starts with an Overall bar. Its length and colour both show the family score.

    A column whose rows all hold the same value is drawn grey, and a warning names it. A figure of one method is grey everywhere.

    5. Your own data¶

    Your data needs raw RNA counts and ATAC as one .h5ad file per batch, with a cell type for each cell. A batch is a donor, a sample or an experiment. mtb.io.export_dataset with batch_index= writes one RNA batch and one ATAC batch per call. iNMF and online_iNMF read ATAC as gene-activity scores, and online_iNMF needs about 5,000 cells in total. Gene-activity scores are an ATAC matrix with one column per gene, as Signac or ArchR compute it.

    Starting from something else? See the recipes for labels in a CSV file and no labels.

    Details: export

    The names in quotes say where your file holds each part. "X" is the main matrix, "obsm:protein" the matrix obsm["protein"], "layer:counts" the layer layers["counts"], and "obs:celltype" the column obs["celltype"], which "celltype" alone names too. A wrong name after obsm:, layer: or obs: raises an error that lists the names the file has.

    The RNA batches and the ATAC batches are numbered separately. RNA batch 1 and ATAC batch 1 need not come from the same sample. scJoint, GLUE, iNMF and online_iNMF read exactly three RNA and three ATAC batches. For another number, such as two donors, write one rna.h5 and one ATAC file with every cell, and pass the batches to run as batch=, one per RNA and ATAC cell, as in Another number of donors.

    For ATAC as a peak matrix, pass atac_kind="peak". GLUE reads the peak matrix.

    "mydata/" + NAME is the dataset folder that scan and run read. With a new value of NAME, the folder holds the files of your data only.

    The check lists the methods you name. Without methods=, it lists every method that reads the modalities in the folder. Its command column holds the line run would execute for each method.

    export_dataset raises FileExistsError when the folder holds files of other cells that the call does not write. overwrite=True does not remove them. Give NAME a new value. A call with batch_index= checks the files of its own batch number. Files of other batch numbers stay: for data with fewer batches, give NAME a new value.

    overwrite=True replaces the files of an earlier run of this cell. Without it, export_dataset raises FileExistsError rather than replace a file.

    The cells below read your data, write it as a dataset folder, check the folder and run the same methods on it. So that the notebook runs as it is, the next cell writes six small example files, my_rna1.h5ad to my_rna3.h5ad and my_atac1.h5ad to my_atac3.h5ad, from the first 900 RNA profiles and the first 900 ATAC profiles of each batch of D37mini. It leaves a file of your own with one of those names as it is.

    6. Every method of this task¶

    4 methods have a variant for diagonal [multiple RNA, multiple ATAC]. Each ran on D37mini in the package's own check, on a server with a GPU:

    Method Result Seconds
    GLUE scored 567
    iNMF scored 16
    online_iNMF scored 8
    scJoint scored 43

    To run them all, set METHODS to these names in section 2 and run the notebook again. That downloads 3 envs, 4.8 GB to download on a CPU host, 8.3 GB on a GPU host. This notebook does the same in Colab.

    The article also evaluates Conos on this task. Its published script reads a third input file in another format, so the package does not run it on more than two files.

    Troubleshooting¶

    res.summary[res.summary.status != "scored"] lists each method that failed or was skipped. Its reason column ends with the method's error output.

    Details
    symptom fix
    env.install refuses on macOS or Windows methods run only on Linux: use Colab or a Linux machine
    a method needs an NVIDIA GPU choose a GPU runtime on Colab, or a machine with a GPU
    a method fails on a small dataset mtb.scan names what the method needs from the data's size in its caveat column
    a warning that values are not whole numbers export raw counts, for example with rna="layer:counts"
    ... matrix/data as cells x features the matrix is transposed: export it again with mtb.io.export_dataset
    a method times out raise timeout= in run
    batch metrics use the wrong batches res.rescore(batch=my_vector) scores again without running the methods
